## Must fix

### 1. Bulk actions run on rows the user never selected

- **Where:** `packages/design-system/src/components/horizon/data-table/index.tsx:350-362`, `:413`
- **What this is:** `IGRPDataTable` remembers which rows are ticked.
- **Problem:** without `getRowId`, a row's identity is its position on the page, and nothing clears the selection when the page or the data changes. The user ticks row 1 on page 1 and goes to page 2: row 1 of page 2 shows as ticked, and "delete selected" deletes it. The dev warning about `getRowId` fires only when `renderSubComponent` is set.
- **Fix:** fire the warning when `selection` is set too. Clear the selection when `data` changes and there is no `getRowId`.
- **If skipped:** users delete or change the wrong records.

### 2. Migrator crash recovery overwrites later edits

- **Where:** `packages/framework/template-migrator/src/commands/apply.ts:56-72`, `unwind.ts:410-428`
- **What this is:** if an earlier `igrp-migrate apply` was killed partway, the next run restores every file from the saved snapshot (the journal).
- **Problem:** it does not check whether the files changed since the crash, and it does not ask first. The user runs `git checkout .`, works on `src/x.ts` for a day, then runs `apply`: that day's work is overwritten.
- **Fix:** restore a file only if its current hash matches what the interrupted step wrote. Otherwise stop with the existing "restore and delete the journal" message.
- **If skipped:** developers lose work; the only notice is one "Recovering…" line.

### 3. Permission pages may return 500 after the access token expires

- **Where:** `packages/framework/next/src/lib/permissions.ts:232-272`, `templates/demo-v1/src/lib/auth.ts:99-103`, `templates/demo-v1/src/app/(igrp)/layout.tsx:23-31`
- **What this is:** `igrpGetClaims` reads permissions from a per-request store (AsyncLocalStorage). `verifySession()` fills that store with the fresh token.
- **Problem:** the template fills the store after an `await`. A value set that way may not reach the layout that awaited it, and Next renders the page in parallel with its layout. The code then falls back to the cookie token, which is not refreshed during a render. A deep link opened after the laptop slept (expired access token, valid refresh token) makes `igrpAssertAuthorize` throw, and every gated section is hidden.
- **Fix:** let `igrpGetClaims`, `igrpAuthorize` and `igrpAssertAuthorize` take an optional token; the template passes `session.accessToken`.
- **If skipped:** gated pages break each time the token expires before the client refreshes it.
- **Not confirmed at runtime:** the Node behaviour was checked with a script; the full app was not run. Reproduce once before fixing.

## Should fix

### 4. One pod can write back a refresh token that is already used

- **Where:** `packages/framework/next-auth/src/session-store.ts:231-243`
- **What this is:** every session write saves the full token set to the shared store (Redis).
- **Problem:** it checks for a newer stored value only when the token carries an error. Pod B reads the old refresh token, pod A refreshes, pod B writes the old token back. The next refresh replays a used token and the identity provider revokes the session. Needs clock drift between pods or a slow write, so it is rare.
- **Fix:** always read the stored value first and keep it when `isNewerHealthy(current, token)` is true (exists at line 490).
- **If skipped:** random logouts on multi-pod deployments.

### 5. The in-memory recovery store drops entries still in use

- **Where:** `packages/framework/next-auth/src/token-store.ts:51`, `:73-82`
- **What this is:** keeps each token refresh for 15 minutes so a later request can recover it; capped at 5000 entries.
- **Problem:** when full, it drops the oldest entry even if not expired. Each active user adds one every 2–3 minutes, so about 1000 users on one pod fill it; a background tab then replays a used token and is logged out. Applies only without a shared store (single replica).
- **Fix:** remove entries only on expiry; memory stays bounded by the 15-minute window.
- **If skipped:** a busy single-pod app logs users out with nothing in the logs.

### 6. Some paths get no security headers and no auth check

- **Where:** `templates/demo-v1/src/middleware.ts:205-211`; same matcher in `packages/framework/next-auth/src/config.ts:176-180`
- **What this is:** the middleware sets the security headers (X-Frame-Options, HSTS, CSP) and checks the session; the matcher picks the paths.
- **Problem:** it skips every path under `/apps` and every path ending in `.pdf`, `.json` and other extensions. An `/apps` page can be framed by another site (clickjacking); a route handler at `/reports/q1.pdf` gets no auth check.
- **Fix:** remove `apps(?:/|$)|` from both matchers. Move the fixed headers into `next.config` `headers()`; keep only the CSP in the middleware.
- **If skipped:** the first such route ships without headers or without auth, and nothing fails.

### 7. The middleware can pass every request while real auth is on

- **Where:** `packages/framework/next-auth/src/middleware.ts:92`
- **What this is:** `igrpMiddlewareDecision` decides whether the auth bypass applies.
- **Problem:** it reads only the env. An app with `withIGRPAuth({ provider: GitHubProvider(...) })` and a leftover `AUTH_PROVIDER=none` runs real auth in the handlers, but the middleware passes every protected path. The template is not affected. The production startup guard may catch this; not confirmed.
- **Fix:** decide the bypass with `auth.isPreviewMode() || auth.isAuthDisabled()`.
- **If skipped:** consumers of the documented `provider` option get an unprotected middleware.

### 8. `fetchMenusAction` puts client input into the URL path

- **Where:** `packages/framework/next/src/actions/index.ts:86-103`
- **What this is:** a server action that loads menus from Access Management (AM) for an `appCode`.
- **Problem:** `appCode` is not checked or encoded. A signed-in user sends `"../../../admin/x?q="` and the server calls another AM GET endpoint with the user's token and returns the result. Nothing in this repo imports the action.
- **Fix:** reject values that fail the existing `APP_CODE_PATTERN` (`sync-plan.ts:63`).
- **If skipped:** any app that imports it gets a proxy into AM GET endpoints.

### 9. A rejected drop removes the file in a single-file dropzone

- **Where:** `packages/design-system/src/components/horizon/input/file.tsx:200-203`
- **Problem:** the user drops `contrato.pdf`, then a 20 MB file that is rejected. The value becomes `null`; the valid file is gone.
- **Fix:** call `updateFiles` only when `newItems.length > 0`.
- **If skipped:** forms submit without their attachment.

### 10. `form.reset()` leaves the old file name in the default file input

- **Where:** `packages/design-system/src/components/horizon/input/file.tsx:548-566`
- **Problem:** the browser file input is uncontrolled. After `reset()` the form value is empty but the input still shows "fatura.pdf".
- **Fix:** when the field value is empty, set `inputRef.current.value = ""` (the dropzone does this at lines 155-163).
- **If skipped:** records are saved without the files the screen showed.

### 11. The number input saves more decimals than it shows

- **Where:** `packages/design-system/src/components/horizon/input/number.tsx:466-493`
- **Problem:** blur rounding ignores `formatOptions`. With currency EUR, `10.005` shows "10,01 €" but submits `10.005`.
- **Fix:** on blur, round to `formatter.resolvedOptions().maximumFractionDigits`.
- **If skipped:** the saved amount differs from the amount the user saw.

### 12. Invalid number text still submits the old value

- **Where:** `packages/design-system/src/components/horizon/input/number.tsx:450-454`, `:478-481`
- **Problem:** the error is visual only. The field holds 50, the user types "abc": the error shows, react-hook-form still submits 50.
- **Fix:** call `setError` on a parse failure, or write `null` so the schema rejects it.
- **If skipped:** a stale value is saved while the screen shows an error.

### 13. A brand save can be ignored for 5 minutes

- **Where:** `packages/framework/next/src/branding/get-branding.ts:82-154`
- **Problem:** the fetch time is recorded when the response arrives. A refresh starts, the admin saves, the refresh returns old data with a newer time, and the pod thinks it has the saved version. `igrpInvalidateBranding` does not cancel a running fetch.
- **Fix:** record the time before the `await`; delete the running fetch on invalidate.
- **If skipped:** "I saved but nothing changed" for up to 5 minutes per pod.

### 14. The cross-site logout guard has no test

- **Where:** `templates/demo-v1/src/app/(auth)/logout/layout.tsx:38-65`
- **What this is:** the only defence against an outside page logging users out (cross-site request forgery), based on `Sec-Fetch-Site` and `Referer`.
- **Problem:** a refactor that weakens it lets any outside link log the user out of every app on the host, and no test fails.
- **Fix:** move the check into a pure function and test 6 cases.

### 22. A locale cookie such as `constructor` crashes all chrome and the global error page

- **Where:** `packages/framework/next-ui/src/i18n/catalogs.ts:15-18`
- **What this is:** `igrpChromeStringsFor` picks the UI strings for a language, falling back to Portuguese. Its comment says it "must never throw".
- **Problem:** it indexes a plain object. `IGRP_LOCALE=constructor` returns the `Object` function, which is truthy, so the fallback never runs and the next string lookup throws. This path runs for every chrome component without an `IGRPChromeI18nProvider`, and for `IGRPGlobalError`. The cookie is `path=/` and not `httpOnly`, so a sibling app or the user can set it.
- **Fix:** `Object.hasOwn(BY_LANGUAGE, language) ? BY_LANGUAGE[language] : IGRP_CHROME_STRINGS_PT`, plus one test with `constructor` and `__proto__`.
- **If skipped:** one cookie value blanks the app, including the last-resort error screen.

### 24. Error copy by `code` never reaches server-thrown errors in production

- **Where:** `packages/framework/next-ui/src/i18n/error-copy.ts:18-26`; `templates/demo-v1/src/app/(igrp)/page.tsx:17-26`; `templates/demo-v1/src/app/(auth)/error.tsx:35`
- **Problem:** in production React sends only `{ digest }` from a server error to the client, so `error.code` is always missing. `IgrpConfigError("IGRP_APP_HOME_SLUG_INVALID")` shows the generic text, not "fix the env var and restart". ### 25. `IGRPLookupField`: typing after a pick keeps the old id

### 26. `IGRPInputSearch` standalone: the caller's `onChange` replaces the internal one

### 27. Multi-step form: Submit fails silently when the error is on an earlier step
