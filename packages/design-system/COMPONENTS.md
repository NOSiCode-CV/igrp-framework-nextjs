# IGRP Design System — Component Map

> Reference for the three-layer model. **Always prefer the Horizon layer.** Drop to Primitives only when Horizon is too opinionated for the use case. Use Custom for IGRP-specific compositions.

## Quick rules

- `IGRP*` from the public root (`@igrp/igrp-framework-react-design-system`) is **always client-side** — files importing it need `'use client'`.
- Forms are always `IGRPForm` + Zod. Never raw `<form>` or direct `react-hook-form`.
- Use semantic tokens (`bg-background`, `text-foreground`, …). Never raw Tailwind colors.
- `cn()` for class merging; `size-*` for equal w/h; `flex gap-*` for spacing.

## IGRP-specific deltas from upstream shadcn

These primitives are intentionally divergent. **Audit them when refreshing from upstream.**

- **`Button`** — adds `xs`, `icon-xs`, `icon-sm`, `icon-lg` sizes beyond the shadcn baseline. Adds `has-data-[icon=inline-end]` / `has-data-[icon=inline-start]` padding tweaks per size.
- **`Accordion`** — `AccordionTrigger` accepts `iconName` / `showIcon` / `iconPlacement` props and renders the chevron via `IGRPIcon` instead of the hard-coded `ChevronDownIcon`, allowing the indicator to be hidden, swapped, or moved to the start; also adds `motion-reduce:animate-none` on the content panel. Reason: lets Horizon wrappers drive iconography from a single source and respect reduced-motion preferences.
- **`Form`** — `FormItem` uses `flex flex-col gap-2` instead of upstream's `grid gap-2` (per the inline `Warning` comment in source), and `FormMessage` adds `role="alert"` so screen readers announce validation errors live. Reason: pre-dating this catalogue; preserved as-is.
- **`Popover`** — `PopoverContent` exposes a `container` prop forwarded to `PopoverPrimitive.Portal` and adds `motion-reduce:animate-none` to the enter/exit animations. Reason: required so popovers (combobox, date picker) can portal into a parent `Dialog`/`Drawer` instead of `document.body`, which otherwise breaks focus management.
- **`Chart`**: `ChartTooltipContent` formats numbers with `toLocaleString` at the IGRP locale (`useIGRPLocale()`) instead of the runtime default, and takes an optional `valueFormatter?: (value: number) => string` that the `IGRP*Chart`s pass their `valueFormatter` into. Reason: SSR-safe number formatting, and one formatter for axes and tooltip.
- **`RadioGroup`** — `RadioGroupItem` adopts a `radioItemVariants` CVA with `variant` (`default` / `outline` / `soft`) and `size` (`sm` / `md` / `lg`) props, and the inner `CircleIcon` indicator scales (`size-1.5` / `size-2` / `size-2.5`) to match the chosen size. Reason: pre-dating this catalogue; preserved as-is.

## Adding a new component — decision flow

1. Does the shadcn skill component table list it? → Add as a Primitive first (copy from upstream via the shadcn CLI's `--diff` flow against a scratch directory).
2. Will every IGRP app want the same labels / icons / loading / form wiring? → Add a Horizon wrapper on top.
3. Is it IGRP-domain-specific (stats card variant, user avatar, status banner)? → Add to `custom/`.

## Strings and locale (`IGRPI18nProvider`)

Every user-visible default string comes from one typed catalog, `IGRPI18nStrings`, shipped in Portuguese (`IGRP_I18N_DEFAULTS_PT`), English (`IGRP_I18N_DEFAULTS_EN`) and French (`IGRP_I18N_DEFAULTS_FR`). Mount `IGRPI18nProvider` once, near the root:

- `strings`: a full catalog, or a deep-partial override merged over `base` (pt by default).
- `locale`: the BCP-47 tag for `Intl` formatting, the calendar's date-fns locale and chart numbers. Always region-qualified (`pt-CV`, not `pt`).

Component label props still win over the provider. Strings use `{token}` placeholders substituted by `igrpFormatMessage`; there are no plurals, so wording must fit any count. Adding a key means adding it to the interface and to all three catalogs; `src/i18n/__tests__/parity.test.ts` fails otherwise. `IGRP_I18N_DEFAULTS_PT_PT` is a deprecated alias of `_PT`.
