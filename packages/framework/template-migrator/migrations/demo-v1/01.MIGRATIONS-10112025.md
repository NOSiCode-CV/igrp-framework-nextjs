## Preview mode

With `IGRP_PREVIEW_MODE=true` the app runs without authentication checks, which is handy for development, demos and tests without a Keycloak setup.

### 1. Middleware (`src/middleware.ts`)

Before, the middleware ran authentication checks and validated the token on every request to a non-public path. It now reads `IGRP_PREVIEW_MODE` first and skips all authentication checks when it is `true`, so nothing redirects to `/login`. The parsing trims whitespace, strips quotes and ignores case.

```typescript
// Skip authentication checks if preview mode is enabled
const rawValue = process.env.IGRP_PREVIEW_MODE;
const previewModeValue = rawValue?.trim()?.replace(/^["']|["']$/g, '')?.toLowerCase();
const isPreviewMode = previewModeValue === 'true';

if (!isPreviewMode) {
  // Authentication checks only run when preview mode is disabled
  if (isPublicPath(pathname)) return NextResponse.next();
  const token = await getToken({ req: request });
  // ... token validation
}
```

### 2. Layout configuration (`src/actions/igrp/layout.ts`)

Before, this always tried to retrieve the access token and returned a `null` session when that failed. In preview mode it now skips token retrieval and returns a mock session instead. The IGRP framework requires a session, so the mock keeps it from seeing a missing one and redirecting on the client, and no Keycloak call is made.

```typescript
const isPreviewMode = previewModeValue === 'true';

// In preview mode, provide a mock session object to prevent client-side redirects
const session = isPreviewMode 
  ? { 
      user: { name: 'Preview User', email: 'preview@example.com' },
      accessToken: 'preview-token',
      expires: '9999-12-31T23:59:59.999Z'
    } as any
  : await getAccessToken();
```

### 3. IGRP layout (`src/app/(igrp)/layout.tsx`)

Before, the layout only checked `previewMode` from the config and could redirect to `/login` when the session was `null`. It now also reads the environment variable, with the same parsing as the middleware, and skips the redirect when either source enables preview mode. The second check covers the case where the config value does not propagate.

```typescript
// Check preview mode directly from environment variable as well
const rawValue = process.env.IGRP_PREVIEW_MODE;
const previewModeValue = rawValue?.trim()?.replace(/^["']|["']$/g, '')?.toLowerCase();
const envPreviewMode = previewModeValue === 'true';
const isPreviewMode = envPreviewMode || previewMode;

if (!isPreviewMode && session === null && urlLogin && !isAlreadyOnLogin) {
  redirect(urlLogin);
}
```

### 4. Template configuration (`src/igrp.template.config.ts`)

Session refetching used to be always on, and a client-side session check could trigger a redirect. In preview mode it now sets `refetchInterval: 0` and `refetchOnWindowFocus: false`, so the client does not poll the session.

```typescript
sessionArgs: (() => {
  const rawValue = process.env.IGRP_PREVIEW_MODE;
  const previewModeValue = rawValue?.trim()?.replace(/^["']|["']$/g, '')?.toLowerCase();
  const isPreviewMode = previewModeValue === 'true';
  
  if (isPreviewMode) {
    return {
      refetchInterval: 0, // Disable refetching
      refetchOnWindowFocus: false, // Disable refetching on focus
      basePath: basePath(process.env.NEXT_PUBLIC_BASE_PATH || ''),
    };
  }
  
  return {
    refetchInterval: 5 * 60,
    refetchOnWindowFocus: true,
    basePath: basePath(process.env.NEXT_PUBLIC_BASE_PATH || ''),
  };
})(),
```

## Custom not-found page

Every unmatched route in the app now shows the same 404 page.

### 1. Root-level not-found page (`src/app/not-found.tsx`)

A new file in the root `app` directory renders the IGRP template component and exports page metadata.

```typescript
import type { Metadata } from "next";
import { IGRPTemplateNotFound } from "@igrp/framework-next-ui";

export const metadata: Metadata = {
  title: "404 - Página não encontrada",
  description: "A página que você está procurando não foi encontrada.",
};

export default function NotFound() {
  const appCode = process.env.IGRP_APP_CODE || "";
  return <IGRPTemplateNotFound appCode={appCode} />;
}
```

It lives at the root because the previous `not-found.tsx` sat inside the `(igrp)` route group, and a route group's `not-found.tsx` only applies to routes in that group.

### 2. Catch-all route (`src/app/[...not-found]/page.tsx`)

A catch-all dynamic route calls `notFound()` for any route nothing else matches, so the custom page is shown even in cases the root file alone would miss.

```typescript
import { notFound } from "next/navigation";

export default function CatchAllNotFound() {
  notFound();
}
```

## Environment variables documentation

`.env.examples` now groups the variables under section headers. Each variable has a comment saying what it does, an example value, how to obtain or set it, and any special notes.

1. Authentication (Keycloak)
   - `KEYCLOAK_CLIENT_ID`
   - `KEYCLOAK_CLIENT_SECRET`
   - `KEYCLOAK_ISSUER`

2. NextAuth
   - `NEXTAUTH_URL`
   - `NEXTAUTH_SECRET` (includes generation commands)
   - `NEXTAUTH_URL_INTERNAL`

3. IGRP framework
   - `IGRP_APP_MANAGER_API`
   - `IGRP_APP_CODE`
   - `IGRP_PREVIEW_MODE` (explains the `true` and `false` values)

4. Next.js public configuration
   - `NEXT_IGRP_APP_CENTER_URL`
   - `NEXT_PUBLIC_BASE_PATH`
   - `NEXT_PUBLIC_IGRP_APP_HOME_SLUG`
   - `NEXT_PUBLIC_ALLOWED_DOMAINS`

## Migration steps

### Enable preview mode

1. Set the environment variable, for example in `.env.local`:

   ```bash
   IGRP_PREVIEW_MODE=true
   ```

2. Restart the development server:

   ```bash
   pnpm dev
   ```

3. Check that the home page loads without authentication and nothing redirects to `/login`.

### Disable preview mode

1. Set the variable to `false`, or remove it:

   ```bash
   IGRP_PREVIEW_MODE=false
   ```

2. Restart the development server.

3. Check that unauthenticated users are redirected to `/login` and session validation works.

## Testing

### Preview mode

1. Set `IGRP_PREVIEW_MODE=true`.
2. Open any route without authentication.
3. Check that no redirect happens.
4. Check the console logs for preview mode detection.

### Not-found page

1. Open a route that does not exist (e.g. `/test-404`).
2. Check that the custom 404 page renders with the IGRP template component.
3. Check that its navigation links work.
