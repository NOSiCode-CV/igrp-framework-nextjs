# 100 — `IGRP_ENABLED_LOCALES` picks the languages a deployment offers

## What changed

| File | Change |
| --- | --- |
| `src/i18n/enabled-locales.ts` | New. `parseEnabledLocales` reads `pt` or `pt,en` into platform locales, drops unknown tags and keeps all three when nothing valid is left. `pickDefaultLocale` keeps `pt` when it is enabled, else takes the first language. |
| `src/i18n/index.ts` | `igrpDefineI18n` gets `locales` from `IGRP_ENABLED_LOCALES` and a `defaultLocale` that is always one of them. |
| `.env.example`, `docs/ENVIRONMENT.md` | Document `IGRP_ENABLED_LOCALES`. |

## Why

Turning the locale switcher off meant editing code. `IGRPLocaleSwitcher` already renders nothing with fewer than two enabled locales, so one env var now hides it in the header and on the login page, with no change to the layouts.

## Behaviour changes to check

None while the variable is unset: all three languages stay enabled. With `IGRP_ENABLED_LOCALES=pt`, the switcher disappears and a stored `IGRP_LOCALE` cookie for `en` or `fr` is ignored. A bad value never stops the app.

If you changed `src/i18n/index.ts`, add only the `locales` line and the `defaultLocale` change.

## After migrating

No framework upgrade needed: `igrpDefineI18n` already accepts `locales`.
