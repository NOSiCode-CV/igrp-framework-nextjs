# 102 — package.json fields, and the test files from 92 and 94 removed

## What changed

| File | Change |
| --- | --- |
| `vitest.config.mts` | `passWithNoTests: true`: `pnpm test` passes in an app with no tests. |
| `package.json` | `version`, `private`, `keywords`, `author`, `license`, `engines` and `scripts` match the template. `name`, `description`, `displayName` and the dependencies are not touched. |
| `src/__tests__/auth-bypass.test.ts` | Deleted (shipped by 92). |

## Why

Until now a migration could change only the dependencies in `package.json`. A new script or engine range in the template reached new apps through the zip, but never reached upgraded apps. The new `pkg.set` step carries those fields, and `check:drift` fails when the template's fields differ from what the migrations leave behind.

Migrations no longer ship test files. Migrations 92 and 94 created 7 of them in upgraded apps. This migration deletes them.

## Behaviour changes to check

- `scripts` is merged: the template's scripts are set, and scripts you added yourself stay. A script with the same name as a template script gets the template's command.
- `version`, `private`, `keywords`, `author`, `license` and `engines` get the template's values. If you changed one of them, set it again after `apply`.
- A test file is deleted only when it still has the content that 92 or 94 wrote. If you changed it, `apply` keeps it and prints a warning.
- `vitest.config.mts` and `vitest` stay. `pnpm test` passes with no tests. Put your own tests under `src/**/__tests__/`.
