# 105 — Accurate comments on where permission claims get their token

## What changed

| File | Change |
| --- | --- |
| `src/lib/auth.ts` | The comment above `igrpEnsureAccessClientConfig` in `getSession()` now says the seed does not reach the `(igrp)` layout. |
| `src/app/(igrp)/layout.tsx` | The comment above `igrpGetClaims()` now says it reads the token through the session read that `withIGRPAuth` registers, not through `verifySession()`. |

Comments only. No code changes.

## Why

The old comments said `getSession()` seeds the token before `igrpGetClaims()` runs. That is not true: a value set after an `await` stays in the async context of the function that set it. With the current `@igrp/framework-next`, `igrpGetClaims()` reads the refreshed access token through the app's session read, which `withIGRPAuth` registers.
