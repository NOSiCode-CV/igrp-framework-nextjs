# 106 — Security headers on every path, a testable logout guard, and auth error copy

## What changed

| File | Change |
| --- | --- |
| `next.config.ts` | New `headers()`: in production, every path gets `X-Content-Type-Options`, `X-Frame-Options`, `X-XSS-Protection`, `Referrer-Policy`, `Permissions-Policy` and `Strict-Transport-Security`. |
| `src/middleware.ts` | Sets only the CSP now; the fixed headers moved to `next.config.ts`. The matcher no longer skips `/apps`. |
| `src/lib/logout-entry.ts` | New. `classifyLogoutEntry(headers)` holds the cross-site logout check from the logout layout, as a pure function. |
| `src/app/(auth)/logout/layout.tsx` | Calls `classifyLogoutEntry`. Same behaviour. |
| `src/app/(auth)/error.tsx` | An `AppError`'s public message is shown before the auth copy. |
| `src/app/(igrp)/page.tsx` | Comment only: the catalog copy for a server-thrown `code` shows only in `next dev`. |

## Why

- The middleware matcher skipped `/apps` and paths that end in a static-asset extension. Those paths got no security headers, so an `/apps` page could be framed by another site. `headers()` in `next.config.ts` has no matcher, so it reaches every path, static files included.
- Matchers are relative to the basePath. The `/apps` exclusion skipped an `/apps` route inside the app, not an app deployed at `/apps/<name>`. With it gone, an `/apps` route gets the auth check like any other page.
- The logout check is the only defence against another site logging the user out. It now has tests.
- In production React sends a server-thrown error to the client as `{ digest }` only. `(auth)/error.tsx` checked for `code` first, which a server error never has, so an `AppError` message was dropped for the generic auth copy.

## Behaviour changes to check

- If your app has a route under `/apps` (inside the app, after the basePath) that must stay public, add its path to `PUBLIC_PATHS` in `src/middleware.ts`. It now needs a session.
- A route handler outside `/api` whose path ends in a static-asset extension (`/reports/q1.pdf`) still skips the middleware. Check the session in the handler, or move it under `/api`.
- If you changed `next.config.ts` or `src/middleware.ts`, these steps replace them. Merge by hand: add the `SECURITY_HEADERS` array and the `headers` entry to `next.config.ts`; in `src/middleware.ts`, delete `SECURITY_HEADERS` and its loop in `withSecurityHeaders`, and remove `apps(?:/|$)|` from the matcher.
- If you already set these headers in a reverse proxy, the browser now receives them twice with the same value. That is harmless; drop one copy if you prefer.
