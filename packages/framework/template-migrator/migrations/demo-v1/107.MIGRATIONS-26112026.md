# 107 — Platform error codes reach the error screen in production

## What changed

| File | Change |
| --- | --- |
| `src/lib/error-copy.ts` | New `hasPlatformCode(error)`: true when the error has a `code`, or its digest carries one (`<id>\|<code>`). |
| `src/app/(auth)/error.tsx` | Uses `hasPlatformCode`, so a server-thrown `IgrpError` keeps its catalog copy instead of the auth copy. |
| `src/app/(igrp)/page.tsx` | Comment only: the catalog copy for `IGRP_APP_HOME_SLUG_INVALID` now shows in production too. |

## Why

In production React sends a server-thrown error to the client as `{ digest }` only, so `code` was lost and the error screen showed the generic copy. `@igrp/framework-next` now puts a machine-stable `IgrpError` code in the digest as `<id>|<code>`, the same shape as an `AppError` digest. Next keeps a digest the error already has. `igrpResolveErrorCopy` in `@igrp/framework-next-ui` reads the code from the digest, and `parsePublicDigest(digest).code` returns it. The error message and context stay on the server.

## Behaviour changes to check

- This needs the `@igrp/framework-next` and `@igrp/framework-next-ui` releases that ship the digest code. With older packages, the screens behave as before.
- The reference shown on the error screen is the part before `|`, as for an `AppError`. For an `IgrpError` it is now a generated id, not Next's hash. Search the server log for that id.
- `parsePublicDigest` now reads a public part shaped like a code (`/^[A-Z][A-Z0-9_]*$/`) as `code`, not `message`. An `AppError` whose `publicMessage` is one upper-case word (`"ERRO"`) now shows the generic copy. Use a sentence.
- If you changed `src/app/(auth)/error.tsx`, merge by hand: replace `"code" in err` with `hasPlatformCode(err)` from `@/lib/error-copy`.
