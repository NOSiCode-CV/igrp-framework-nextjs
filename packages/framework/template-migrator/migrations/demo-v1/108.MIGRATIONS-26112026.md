# 108 — `/login?reason=session_ended` checks the origin; `/api/csp-report` logs 3 fields; bypass helpers removed

## What changed

| File | Change |
| --- | --- |
| `src/app/(auth)/login/page.tsx` | `reason=session_ended` runs the local sign-out only when `classifyLogoutEntry` (from migration 106) does not answer `confirm`. A link from another site sees the normal login flow. |
| `src/lib/csp-report.ts` | New `summarizeCspReport(body)`: reads the `report-uri` and Reporting API shapes, returns `document`, `directive` and `blocked`, each cut to 200 characters, or `null`. |
| `src/app/api/csp-report/route.ts` | Logs the summary only. A body that is not a CSP report gets `400`. |
| `src/lib/utilities.ts` | `isPreviewMode()` and `isAuthDisabled()` removed. `isAuthBypass()` is the one check. |
| `src/lib/auth-instance.ts` | Comment only: no longer names `withAuth`, which `@igrp/framework-next-auth/middleware` no longer exports. |

## Why

Audit 2026-11-25, items 17, 18 and 20.

- Any site could link to `/login?reason=session_ended` and sign the user out of the app. `/logout` already refused that; `/login` now applies the same `Sec-Fetch-Site` check.
- `/api/csp-report` is public and logged any body up to 8 KB. Anyone could write 8 KB of text into the server log per request.
- `isPreviewMode()` and `isAuthDisabled()` had no caller and invited a check of only one of the two bypass modes. The rule is to use `isAuthBypass()`.

## Behaviour changes to check

- The framework's own redirects to `?reason=session_ended` are same-origin (the session watcher, the 401 path of the layout data) or come from the middleware during a navigation in the app, so they keep working.
- A user who arrives from another site with a session that a co-hosted app's logout ended no longer has the local session cleared first. They see the login flow, and signing in replaces the old session.
- The CSP log line is now `[csp-report] {"document":…,"directive":…,"blocked":…}`. Update any log search that read the raw report.
- If your own code imports `isPreviewMode` or `isAuthDisabled` from `@/lib/utilities`, the build fails. Use `isAuthBypass()`, or `isPreviewModeEnabled(process.env)` / `isAuthDisabled(process.env)` from `@igrp/framework-next-auth/providers` when you need only one mode.
- If you changed `src/app/(auth)/login/page.tsx`, merge by hand: import `headers` from `next/headers` and `classifyLogoutEntry` from `@/lib/logout-entry`, and add `&& classifyLogoutEntry(await headers()) !== "confirm"` to the `reason === "session_ended"` check.
