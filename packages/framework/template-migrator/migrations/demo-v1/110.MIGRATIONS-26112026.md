# 110 — Send only the client message namespaces to the browser; home page renders on the server

## What changed

| File | Change |
| --- | --- |
| `src/i18n/index.ts` | `clientNamespaces: ["auth", "errors"]`. The root layout now sends only these namespaces (plus the framework's `i18n`) to the browser. |
| `src/components/home-overview.tsx` | A Server Component (`getTranslations`), no longer `"use client"`. |
| `src/components/copy-button.tsx` | New. The copy button, the only interactive part of the home page. It gets its labels as props. |
| `src/app/layout.tsx` | `generateMetadata` loads the branding and the `app` messages in parallel. |
| `src/app/(igrp)/page.tsx` | Loads the `home.layers` messages in parallel with the session and claims. |

## Why

Performance review against the Vercel React rules. Without `clientNamespaces`, every page carried the whole message catalog in its HTML and RSC payload, about 3.7 KB of the 5 KB app catalog (`home`, `login`, `notFound`, `app`), although no Client Component reads them. The home page hydrated its whole tree for one copy button.

## Behaviour changes to check

A Client Component that calls `useTranslations("<ns>")` for a namespace not in `clientNamespaces` now gets a `MISSING_MESSAGE` error. If your app has Client Components with their own namespaces, add those namespaces to `clientNamespaces` in `src/i18n/index.ts`, or pass the strings down as props from a Server Component. Server code (`getTranslations`) is not affected.

If you changed `src/app/layout.tsx`, `src/app/(igrp)/page.tsx` or `src/i18n/index.ts`, copy only the changes listed above into your files. If you replaced the home page, you can delete `src/components/home-overview.tsx` and `src/components/copy-button.tsx`.

## After migrating

Needs `@igrp/framework-next` 0.2.0-beta.24 or later (`i18n.clientNamespaces`).
