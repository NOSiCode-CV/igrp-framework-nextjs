# 32 — Turbopack root probe + resync to beta.169

Re-captures `next.config.ts` and re-pins the two `@igrp/*` packages published in
the beta.169 wave.

## `next.config.ts` — stop assuming a monorepo parent

`turbopackRoot` was hardcoded to `path.resolve(appDir, "../..")`. That is correct
inside this monorepo, where the template lives at `templates/demo-v1`, but wrong
for a standalone app: it points Turbopack two directories **above** the app, so
it traverses (and watches) unrelated sibling projects — or the drive root.

It now probes for the workspace marker and falls back to the app itself:

```ts
const appDir = path.dirname(fileURLToPath(import.meta.url));
const monorepoRoot = path.resolve(appDir, "../..");

const turbopackRoot = existsSync(path.join(monorepoRoot, "pnpm-workspace.yaml"))
  ? monorepoRoot
  : appDir;
```

Monorepo checkouts keep the old behaviour (the marker is there, so the pnpm
`.pnpm` store stays in scope for symlink resolution); standalone apps root at
their own directory.

**If you customised `next.config.ts`**, this is a `replace` step — the migrator
captures your current file in `undoPayloads` so `rollback` can restore it, but
re-apply your own edits on top afterwards.

## What changed upstream

- **`@igrp/framework-next-ui@0.1.0-beta.165`** — two layout-resilience fixes:
  - "Tentar novamente" in the header/sidebar error fallbacks now actually
    retries. `IGRPLayoutErrorBoundary` latched `hasError` permanently, so the
    `router.refresh()` behind the button re-fetched the server tree while the
    boundary kept rendering the error. The boundary now exposes a reset through
    context, and the fallbacks refresh inside a transition and clear the
    boundary only once it settles. `useIGRPLayoutRetry` and
    `useIGRPLayoutErrorReset` are exported for custom fallbacks.
  - Runtime-supplied image hosts no longer take down the layout.
    `IGRPTemplateAppSwitcher` and `IGRPTemplateHeader` rendered app pictures and
    the header logo through `next/image`'s default loader, which throws for any
    host missing from the app's `images.remotePatterns` — and those URLs come
    from the access-management backend at runtime, so consumers cannot whitelist
    them up front. Both now render through an internal `IGRPTemplateImage` that
    marks remote sources `unoptimized` and falls back to the icon (or the
    bundled logo) when an image fails to load.
- **`@igrp/framework-next@0.1.0-beta.169`** — bumped by the internal-dependency
  cascade, not by a change of its own; it depends on `next-ui`.

## Notes for upgraders

- Run your package manager's install afterwards (`pnpm install`). `deps.bump`
  rewrites `package.json` only — it does not touch your lockfile.
- The `remotePatterns` entries you already have keep working; the framework no
  longer *requires* them for backend-supplied images.
