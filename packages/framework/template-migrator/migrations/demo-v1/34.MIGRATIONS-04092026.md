# 34 — Header slots, and a search palette that actually has commands

Adds two files and wires them into the `(igrp)` layout:

- `src/lib/header-search.ts` — resolves the application menus into serializable
  command data (server-side).
- `src/components/header/app-search.tsx` — the client command palette, built on
  `IGRPTemplateCommandSearch`.
- `src/app/(igrp)/layout.tsx` — passes the palette to `IGRPLayoutFull` through the
  new `headerSlots` prop.

It also re-pins the three `@igrp/*` packages published in this wave:

| Package | Pinned to |
| --- | --- |
| `@igrp/igrp-framework-react-design-system` | `0.1.0-beta.144` |
| `@igrp/framework-next-ui` | `0.1.0-beta.166` |
| `@igrp/framework-next` | `0.1.0-beta.170` |

The pins are **not** optional: `headerSlots` does not exist before
`framework-next` beta.170 / `framework-next-ui` beta.166, so the layout this
migration writes would not type-check against the ranges migration 32 pinned.
Everything else stays on the ranges migrations 31–32 set (last-writer-wins).

## Why

Two separate things landed here.

**The framework gained header slots.** `IGRPLayoutFull` now accepts
`headerSlots`, letting an app inject its own components into positions the
framework owns:

| Slot | Position | Gating |
|---|---|---|
| `start` | Left region, after the logo/title, before the breadcrumbs | Presence of the node |
| `search` | Right cluster, replaces the built-in palette | `showSearch` |
| `notifications` | Right cluster, replaces the built-in dropdown | `showNotifications` |
| `settings` | Right cluster, replaces the built-in settings link | `showSettings` |
| `actions` | Right cluster, after notifications, before the theme switcher | Presence of the node |

The framework still fetches and owns **all** header data — user, logo,
breadcrumbs, sidebar trigger. A slot only decides what renders in its position,
never where the data comes from. Slots are React *elements*, not component
references: they cross the Server→Client boundary into `IGRPTemplateHeader`, and
functions cannot. Each slot renders in its own `<Suspense>`, so an async Server
Component slot can't delay the rest of the bar.

**The built-in search was empty.** `IGRPTemplateHeader` mounted
`<IGRPTemplateCommandSearch />` with no `commands` prop, so `⌘K` opened a palette
that could never contain anything. This migration supplies a real one, derived
from the application menus, which is also the reference example of how to use a
slot.

## Impact on your app

- **`⌘K` / `Ctrl+K` now lists your menu pages** and navigates to them. Items are
  grouped by their parent folder; external menu entries open in a new tab.
- **Menu resolution follows the sidebar's own branching**: mock menus under
  either auth-bypass mode (`IGRP_PREVIEW_MODE=true` or `AUTH_PROVIDER=none`), the
  access-management menus otherwise.
- **A failed menu fetch yields an empty palette, not a broken header.** Search is
  auxiliary chrome. A 401/403 still propagates, because `fetchMenusAction`
  rethrows the redirect that signals an invalid session.
- **If you supply a `notifications` slot**, the framework also suppresses the
  link-only "Notifications" entry inside the nav-user dropdown — otherwise the
  header would offer two inconsistent entry points, one of which your component
  doesn't own. Your slot is not hidden on small screens (the framework's own bell
  is, because nav-user carries the mobile entry).
- **`typedRoutes: true`** means `router.push()` is typed against statically known
  routes. Menu hrefs arrive at runtime, so `app-search.tsx` casts at that
  boundary. If you resolve navigation targets from runtime data elsewhere, you'll
  need the same cast.

## If you customised `src/app/(igrp)/layout.tsx`

This step **replaces** that file. It is a file apps commonly edit — extra
providers, permission wrappers, custom breadcrumbs. Before migrating, diff your
version against the payload and re-apply your changes afterwards. The layout
change itself is small and easy to port by hand:

```tsx
import { AppSearch } from "@/components/header/app-search";
import { getHeaderSearchCommands } from "@/lib/header-search";

const searchCommands = await getHeaderSearchCommands(config);

<IGRPLayoutFull
  config={config}
  headerSlots={{ search: <AppSearch commands={searchCommands} /> }}
>
```

If you already have your own command palette, keep it and pass it as the `search`
slot instead — you can skip `header-search.ts` and `app-search.tsx` entirely. If
you'd rather keep the framework's (empty) built-in, drop the `headerSlots` prop;
nothing else in this migration depends on it.
