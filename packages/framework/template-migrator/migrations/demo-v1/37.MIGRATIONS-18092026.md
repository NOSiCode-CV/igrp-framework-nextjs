# 37 — `cn` comes from the package; `src/lib/utils.ts` is retired

Catch-up migration. The template stopped defining its own `cn` helper and took
the [`cn`](https://www.npmjs.com/package/cn) package instead — "fast, small,
compiled class-name merging for Tailwind CSS, a drop-in replacement for clsx +
tailwind-merge". Two files changed their import:

```diff
-import { cn } from "@/lib/utils";
+import { cn } from "cn";
```

- `src/app/(auth)/login/page.tsx`
- `src/lib/fonts.ts`

`cn` was the last thing `src/lib/utils.ts` exported — the rest of its helpers
had already moved to `src/lib/utilities.ts` (shipped by migration 26, which is
why `isAuthBypass` / `sanitizeCallbackUrl` import from there). With no consumers
left, the file is deleted.

## If you don't have `cn`

**`deps.bump` does not add a dependency your app doesn't declare** — it updates
an existing range, and otherwise prints:

```
⚠ package.json: not declared by this app, so NOT bumped: cn@^0.3.0
```

That warning is load-bearing here: the two files this migration writes import
from `cn`, so if you see it, install the package before building.

```bash
pnpm add cn@^0.3.0
```

## If you customised either file

Both steps **replace** the file. `src/lib/fonts.ts` is commonly edited (font
choices, weights, CSS variable names) — diff it against the payload and
re-apply. The change itself is one import line in each file, so porting by hand
is trivial if you'd rather keep your own version; in that case you still want
the dependency, and you can skip the `file.delete` if something of yours still
imports `@/lib/utils`.

## Why this is a catch-up

These three changes were made directly in the template without a migration, so
the drift gate had been failing on them. Nothing here is new behaviour — it
brings the shipped migrations back in line with what `templates/demo-v1` has
actually contained since then, so a scaffolded app and an upgraded app agree
again.
