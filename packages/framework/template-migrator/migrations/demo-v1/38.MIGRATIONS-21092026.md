# 38 — `createConfig` is annotated with `IGRPConfigClient`; the layout casts go

Three files, one change: the template's config factory now declares its type
instead of being inferred, and the two `as` casts that existed only because the
type was wrong are removed.

## `src/igrp.template.config.ts`

```diff
-import type {
-  IGRPConfigArgs,
-  IGRPLayoutConfigArgs,
-} from "@igrp/framework-next-types";
+import type { IGRPConfigClient } from "@igrp/framework-next-types";

-export function createConfig(
-  config: IGRPLayoutConfigArgs,
-): Promise<IGRPConfigArgs> {
+export const createConfig: IGRPConfigClient = (config) => {
   ...
-}
+};
```

`IGRPConfigClient` has existed for several releases but **nothing could apply
it**: it read `() => Promise<IGRPConfigArgs>` and its docs pointed at a *default*
export, while the real factory is a named export taking the per-request layout
config. It now reads `(config: IGRPLayoutConfigArgs) => Promise<IGRPConfigArgs>`,
which is the shape the template has always had.

Annotating the factory moves the check to the definition site: a misspelled or
missing key in the object passed to `igrpBuildConfig` now fails in
`igrp.template.config.ts` rather than wherever the config is eventually consumed.

## `src/app/layout.tsx` and `src/app/(igrp)/layout.tsx`

```diff
-import type { IGRPLayoutConfigArgs } from "@igrp/framework-next-types";
-
-  const config = await createConfig(layoutConfig as IGRPLayoutConfigArgs);
+  const config = await createConfig(layoutConfig);
```

The cast was never load-bearing — `getLayoutConfig()` already returns something
assignable to `IGRPLayoutConfigArgs`, verified by removing the cast and running
`tsc --noEmit` clean. An `as` on a cross-package type is exactly what hides the
next drift, so it is better gone. With the cast removed the type import has no
remaining use in either file and is dropped too.

## Prerequisite

> **This migration requires the `@igrp/framework-next-types` published in the
> same release wave.** The corrected `IGRPConfigClient` signature only exists
> from that version onward; against an older pin, `igrp.template.config.ts`
> fails to compile with "Expected 0 arguments, but got 1". The accompanying
> dependency-resync migration pins it — apply the two together.

## If you customised these files

All three steps **replace** the file. `igrp.template.config.ts` is the one most
likely to have been edited (app code, mock data wiring, `apiManagementConfig`).
Diff it against the payload before applying; the change itself is the import line
plus the function-to-const conversion, so porting by hand is straightforward if
you would rather keep your own version.
