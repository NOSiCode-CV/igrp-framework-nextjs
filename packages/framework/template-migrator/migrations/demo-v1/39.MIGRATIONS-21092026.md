# 39 — `layoutMockData` becomes `layoutData`

`layoutMockData` was production configuration wearing a preview-mode name.

Both framework providers call it on **every** render in **both** modes —
`SidebarDataProvider` calls `getSidebarData()` before it branches on
`previewMode` at all — and production overrides only the fields Access
Management can supply:

| Returned by        | Overridden in production          | Live in production                                                                                         |
| ------------------ | --------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `getHeaderData()`  | `user`, `showIGRPSidebarTrigger`  | every other `show*` flag, `settingsUrl`, `settingsIcon`, `notificationsUrl`, `userProfileUrl`, `headerLogo` |
| `getSidebarData()` | `user`, `menuItems`, `apps`, `appCode` | `defaultOpen`, `showAppSwitcher`, `appCenterUrl`, `showMenuSearch`, `showNotifications`                |

An app author who read the name and returned a stub in production — or gated the
whole factory behind `previewMode` — lost the entire header and sidebar
configuration. No error, no type complaint; the chrome just rendered nothing.

## `src/igrp.template.config.ts`

```diff
-    layoutMockData: {
+    layoutData: {
       getHeaderData: async () => { ... },
       getSidebarData: async () => { ... },
     },
```

## `src/lib/header-search.ts`

The auth-bypass branch read the field directly. It now goes through the
framework's resolver, which handles both spellings for the duration of the
deprecation window:

```diff
+import { igrpResolveLayoutDataSource } from "@igrp/framework-next";

-  const { menuItems } = await config.layoutMockData.getSidebarData();
+  const { menuItems } = await igrpResolveLayoutDataSource(config).getSidebarData();
```

## Compatibility

`@igrp/framework-next-types` keeps `layoutMockData` as a `@deprecated` optional
field and `IGRPMockDataAsync` as an alias of the new `IGRPLayoutDataSource`, so
an app that has not applied this migration keeps working. **Setting both keys is
rejected** (`IGRP_CONFIG_INVALID`) rather than silently merged — the two can
disagree and there is no principled winner.

Both are removed one release after this one.
