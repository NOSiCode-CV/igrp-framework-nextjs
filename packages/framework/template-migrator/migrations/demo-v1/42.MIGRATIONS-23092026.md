# 42 — stream the header search, drop unused fonts, de-action the layout helpers

Outcome of a React/Next.js performance review of the template. No new
dependencies, no env changes, no framework version requirement.

## What changed

| File | Change |
| --- | --- |
| `src/app/(igrp)/layout.tsx` | Header search commands stream behind `<Suspense>` instead of blocking the layout; `verifySession()` and `getLayoutConfig()` run in parallel |
| `src/actions/igrp/layout.ts` | `"use server"` → `import "server-only"` |
| `src/lib/fonts.ts` | Removed `Inter` and `Mulish`; `Geist_Mono` no longer preloaded |
| `src/styles/themes.css` | Removed the dead `--font-sans: var(--font-inter)` override from `:root` |
| `src/app/(auth)/login/page.tsx` | Re-capture: comment above the `/cn` import trimmed (no code change) |

### 1. The header search no longer blocks every authenticated page

`getHeaderSearchCommands()` makes a live Access Management call (the user's
application menus). It used to be `await`ed in the layout body, outside any
Suspense boundary, so the first byte of **every** authenticated page waited for
it — up to the AM client timeout — and the header/sidebar skeletons that
`IGRPLayoutFull` streams behind their own boundaries never got a chance to show.

The promise is now started in the layout body (so it runs in the same async
context as before, where the per-request access-client store lives) and
awaited inside a small `AppSearchSlot` server component wrapped in
`<Suspense fallback={<AppSearch commands={[]} />}>`. The sidebar still shares
the same per-request menu fetch (`React.cache` in the framework), so there is
no extra AM call.

### 2. Fonts: two families instead of four

`--font-mullish` (Mulish) was referenced nowhere. `Geist` and `Inter` both
wrote `--font-sans` on `<html>` with equal specificity; `fonts.ts` is imported
after `globals.css`, so Geist won and Inter was downloaded for nothing. Both
are removed, which leaves the rendered font unchanged (Geist) and drops the
font preloads on every page, `/login` included, from four to one — `Geist_Mono`
is only used by the `theme-mono` theme and `font-mono` utilities, so it is no
longer preloaded.

**If you have customised `fonts.ts` or `themes.css`**, `apply` stops and names
them instead of overwriting (only `--force` overwrites). Port the change by
hand: delete the `Inter`/`Mulish` loaders, add `preload: false` to
`Geist_Mono`, and drop `--font-sans: var(--font-inter)` from `:root`. If your
app deliberately wants Inter, give Inter the `--font-sans` variable in
`fonts.ts` instead of setting it in `:root`, where it loses to the next/font
class.

### 3. `actions/igrp/layout.ts` is no longer a `"use server"` module

`getTheme()` and `configLayout()` are only ever called from server components.
Under `"use server"` every export is a Server Action candidate: the moment a
client component imported the file, `configLayout` would become a public POST
endpoint returning the session. The path and exports are unchanged, so
existing `import { configLayout } from "@/actions/igrp/layout"` keeps working
— from server code only, which `server-only` now enforces at build time.

### 4. Login page re-capture

The template's `login/page.tsx` lost the comment explaining why `cn` comes from
the `/cn` subpath (the same rationale is documented in `src/lib/fonts.ts` and
in `.agents/rules/ui.md`). Comment-only; re-captured so scaffolded and upgraded
apps agree.

## Related framework change

`@igrp/framework-next-auth` now memoizes `getServerSession` per RSC render, so
the root layout and `(igrp)/layout.tsx` share one session decode. That lands
with the next framework release and needs no template change.
