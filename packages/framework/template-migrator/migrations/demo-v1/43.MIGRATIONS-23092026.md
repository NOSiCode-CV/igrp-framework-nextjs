# 43 — make `/api/health` reachable without a session

One file, one line of behaviour.

## What changed

| File | Change |
| --- | --- |
| `src/middleware.ts` | `/api/health` added to `PUBLIC_PATHS` |

## Why

The container `HEALTHCHECK` (`docker/*/Dockerfile`, see `docs/DOCKER-RUN.md`)
polls `/api/health` with `wget`. The middleware matcher covers `/api/*`, and
`/api/health` was not public, so without a session it answered
**307 → `/login`**. `wget` follows redirects, so the probe:

- tested the **login page** — at the public origin the redirect points to — and
  never reached the health route, and
- failed outright when the container cannot reach that public origin, marking a
  working app `unhealthy`.

Measured before the fix against a production build with auth on:

```
GET /apps/template/api/health  → 307  Location: …/login?callbackUrl=%2Fapi%2Fhealth
```

After: `200 {"status":"Up",…}`. Protected pages still redirect to `/login`.

The route returns only a static status and timestamp, so exposing it is safe.
If you customised `src/middleware.ts`, `apply` stops and names it instead of
overwriting; add `"/api/health"` to `PUBLIC_PATHS` by hand.
