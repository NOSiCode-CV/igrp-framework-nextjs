# 44 — keep Node-only code out of the Edge middleware

## What changed

| File | Change |
| --- | --- |
| `src/lib/auth-instance.ts` | **New.** The `withIGRPAuth` instance and `PREVIEW_SESSION_STUB`, moved out of `lib/auth.ts` |
| `src/lib/auth.ts` | Re-exports `auth` and `PREVIEW_SESSION_STUB` from `auth-instance`; keeps `serverSession()` / `getSession()` |
| `src/middleware.ts` | Imports `auth` from `@/lib/auth-instance` instead of `@/lib/auth` |
| `src/lib/fonts.ts` | Comment only: the `cn` note now matches the current design system |

## Why

Every `next build` printed:

```
A Node.js module is loaded ('node:async_hooks' at line 7) which is not supported in the Edge Runtime.
Import trace:
  Edge Middleware:
    ./packages/framework/next/dist/lib/api-config.js
    ./templates/demo-v1/src/lib/auth.ts
    ./templates/demo-v1/src/middleware.ts
```

Middleware runs on the Edge runtime and only needs the `auth` instance, but
`lib/auth.ts` also holds the server session helpers, which import
`igrpSetAccessClientConfig` from `@igrp/framework-next`, and that is built on
`node:async_hooks`. The instance now lives in its own Edge-safe module; the
build no longer warns.

**No import changes are needed in your code.** `@/lib/auth` still exports
`auth`, `PREVIEW_SESSION_STUB`, `serverSession` and `getSession`. Only
middleware should import from `@/lib/auth-instance`, and nothing Node-only
(including anything from `@igrp/framework-next`) may be imported there.

If you customised `lib/auth.ts` (for example, a different provider or extra
`withIGRPAuth` options) or `middleware.ts`, `apply` stops and names them. Port
by hand: move the `withIGRPAuth(...)` call and its helpers into
`src/lib/auth-instance.ts`, re-export them from `lib/auth.ts`, and point the
middleware import at `@/lib/auth-instance`.

## Optional manual step: agent rules

`.agents/rules/ui.md` was updated in the template: the `'use client'` and
`cn` rules no longer say the design system's root is a client boundary (it
stopped being one after `0.1.0-beta.146`). The advice itself is unchanged, and
this file isn't migration-managed, so `apply` won't overwrite your copy. Copy
the two bullets from a freshly scaffolded app if you want the corrected
wording.
