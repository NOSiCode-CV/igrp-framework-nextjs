# 45 — `pnpm dev` prints the app URL under `NEXT_PUBLIC_BASE_PATH`

## What changed

| File | Change |
| --- | --- |
| `scripts/dev.mjs` | **New.** Wraps `next dev --turbopack` and prints the app URL, basePath included, under Next's `Local:` line |
| `package.json` | `"dev"` script is now `node scripts/dev.mjs` (**manual step, see below**) |

## Why

With `NEXT_PUBLIC_BASE_PATH=/apps/template`, Next's startup banner only shows
the server root (`http://localhost:3000`), which 404s. The dev banner now also
shows the URL the app is actually served at:

```
   - Local:        http://localhost:3000
   - App:          http://localhost:3000/apps/template
```

The wrapper reads `NEXT_PUBLIC_BASE_PATH` from the shell, then
`.env.development.local`, `.env.local`, `.env.development` and `.env` (Next's
development precedence). It takes host and port from Next's own `Local:` line,
so the URL stays correct when Next falls back to another port. Extra arguments
pass through (`pnpm dev -p 4000`). With no basePath the output is unchanged.
It has no dependencies beyond Node (>= 22) and the app's own `next`.

## Manual step: `package.json`

`package.json` isn't migration-managed (it holds your own dependencies), so
`apply` only adds `scripts/dev.mjs`. Point the `dev` script at it:

```diff
-    "dev": "next dev --turbopack",
+    "dev": "node scripts/dev.mjs",
```

If you skip this, nothing breaks: `pnpm dev` behaves as before and the new
file is unused.
