# 47 — Turbopack alias for `lucide-react/dynamicIconImports`

## What changed

| File | Change |
| --- | --- |
| `next.config.ts` | Adds `turbopack.resolveAlias` mapping `lucide-react/dynamicIconImports` to the design system's own copy of `lucide-react/dynamicIconImports.mjs` |
| `src/components/header/app-search.tsx` | Drops the comment above `router.push()`. No behaviour change |
| `package.json` | `@igrp/platform-access-management-client-ts` → `0.2.0-beta.17` |

## Why

The design system is ESM and imports `lucide-react/dynamicIconImports` with no
file extension. `lucide-react` has no `exports` map, so strict ESM resolution
can't find the `.mjs` file and the build fails.

The alias points at the `lucide-react` next to the design system's resolved
location (`realpathSync` follows pnpm's symlink into `.pnpm/…`). `lucide-react`
is a peer of the design system, not a direct dependency of the app, so the app
can't resolve it by name. The path works with both pnpm's nested layout and
npm's hoisted layout.

Remove the alias once the design system imports the full `.mjs` path.

## Manual steps

None. Run `pnpm install` after applying to pick up the dependency bump.
