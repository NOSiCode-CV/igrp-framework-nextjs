# 53 — Home redirect, scoped logout marker, safer `getAuthenticatedUser`

## What changed

| File | Change |
| --- | --- |
| `next.config.ts` | `/` → `NEXT_PUBLIC_IGRP_APP_HOME_SLUG` is now a config `redirects()` entry |
| `src/app/(igrp)/page.tsx` | comment only — its `redirect()` is now a fallback |
| `src/lib/dal.ts` | `getAuthenticatedUser()` no longer returns `accessToken`; module is `server-only` |
| `src/lib/logout-pending.ts` | the `logout_pending` cookie name carries the basePath suffix |
| `src/config/site.ts` | drops `logo.srcDark`, which pointed at the same file as `logo.src` |

No dependency or environment changes.

## Why

- **Home redirect.** The page's `redirect()` only ran after `(igrp)/layout.tsx`
  had verified the session, built the config, and started the Access Management
  menu fetches — all discarded. A config redirect runs before middleware and
  renders nothing. An invalid slug (no leading `/`) gets no redirect, so the page
  still throws `IGRP_APP_HOME_SLUG_INVALID` as before.
- **`getAuthenticatedUser()`.** It was documented as returning "only the user
  fields UI components need" but included the access token, so passing its
  result to a client component put the bearer token in the page payload.
- **`logout_pending`.** A root-path app writes this marker at `path=/`, which
  the browser sends to every app on the host. Another app's middleware read it,
  forced `/login`, and its `LogoutCompletion` signed the user out of that app
  too. The name now uses `basePathCookieSuffix`, like the silent-SSO cookie.
- **`logo.srcDark`.** When set, the login form renders a second `<Image>`; with
  the same file in both it was pure overhead.

## ⚠️ Breaking for custom code

- Code reading `getAuthenticatedUser().accessToken` stops compiling. Read the
  token server-side from `verifySession()` instead, and never pass it to a
  client component.
- If you set a distinct dark logo, put `srcDark` back in `src/config/site.ts`.

## Deploy note

A logout already in flight during the deploy (marker set, IdP round-trip not
finished) is written under the old name, so the new code won't see it. The local
session survives that one logout; signing out again finishes it. The old cookie
expires on its own within 5 minutes.
