# 54 — Home page shows this request's path through the app

## What changed

| File | Change |
| --- | --- |
| `src/components/home-overview.tsx` | new — the home page UI (client component, design system only) |
| `src/app/(igrp)/page.tsx` | renders `HomeOverview` instead of the "IGRP NEXT.js Template" placeholder |

No dependency or environment changes.

## Why

The placeholder told a new team nothing. The home page now shows, for the
current request, what each layer did — middleware, session, Access Management,
permissions, the page itself — with the file to change for each. A missing
`IGRP_ACCESS_MANAGEMENT_API` or an unreadable token shows up here, in red,
instead of on a later page. Below it: the four steps to add a first module.

The page still only renders when `NEXT_PUBLIC_IGRP_APP_HOME_SLUG` is empty;
with a slug set, `/` redirects as before (see migration 53).

Nothing sensitive reaches the browser: the server passes plain strings — no
token, no claim list, no Access Management URL.

## ⚠️ If you customised the home page

`page.tsx` is replaced. If your app already shows its own content at `/`,
either keep your file (skip this migration's `page.tsx` step) or move your
content to its own route and point `NEXT_PUBLIC_IGRP_APP_HOME_SLUG` at it.
