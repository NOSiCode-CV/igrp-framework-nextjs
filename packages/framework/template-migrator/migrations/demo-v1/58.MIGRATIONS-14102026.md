# 58 — Internationalisation: framework i18n, language switcher, chrome catalog

## What changed

| File | Change |
| --- | --- |
| `src/i18n/**` | new: `igrpDefineI18n` config, next-intl request config, `setLocale` action, catalogs, typed keys |
| `next.config.ts` | `createNextIntlPlugin("./src/i18n/request.ts")`; i18n subpaths in `optimizePackageImports` |
| `src/igrp.template.config.ts` | `igrpBuildConfig({ i18n })` |
| `src/app/(igrp)/layout.tsx` | `IGRPLocaleSwitcher` in the header `actions` slot |
| `src/app/(auth)/login/page.tsx` | `IGRPLocaleSwitcher` on the login page |
| `src/app/global-error.tsx`, `error.tsx`, `(igrp)/error.tsx`, `(auth)/error.tsx` | copy comes from the framework chrome catalog; `src/lib/error-copy.ts` keeps only the public-digest description |
| `src/config/error-messages.ts` | removed |
| `src/components/home-overview.tsx`, `src/app/(igrp)/page.tsx` | translated (`home` namespace), the worked example |
| `src/middleware.ts` | comment only (cookie-first apps need no change) |
| `src/config/login.ts` | `loginButton` removed: the chrome catalog supplies the label in the current language |
| `docs/I18N.md` | new guide |
| `.env.example` | replaced (adds the documented `IGRP_FORMAT_LOCALES` key); copy the new block into your `.env` if you keep a custom example |

## Manual steps (this migration cannot add what the app did not declare)

1. `package.json`: bump to the first release that ships the i18n runtime: `@igrp/framework-next` and `@igrp/framework-next-ui` `0.2.0-beta.8`, `@igrp/framework-next-auth` and `@igrp/framework-next-types` `0.2.0-beta.7`, `@igrp/igrp-framework-react-design-system` `0.2.0-beta.5` (migration 61 bumps these for you). Add `"next-intl": "^4.14.0"` to `dependencies` and `"@igrp/framework-next-i18n": "0.2.0-beta.1"` to `devDependencies`.
2. `package.json` scripts: add `"lint:i18n": "igrp-i18n check-catalogs src/i18n/messages --default pt && igrp-i18n check-literals src/components src/i18n \"src/app/(igrp)/page.tsx\""` and prepend `pnpm lint:i18n &&` to `next build` in `build` (after `pnpm lint`).
3. `pnpm install`.

## Why

Every IGRP app now shares one locale (`IGRP_LOCALE` cookie, path `/`), one resolution order and three complete string sets: the design system, the template chrome (header, menus, error screens, platform error codes) and the app's own messages. Picking English in one app no longer leaves half the screen in Portuguese. Design: `docs/superpowers/specs/2026-10-12-framework-i18n-v2-design.md` in the framework repository.

## ⚠️ If you customised these files

Every `file.write` step replaces the whole file. `apply` aborts when a managed file differs from the previous baseline; re-apply your changes on top of the new file rather than forcing.

| File | What to re-apply by hand |
| --- | --- |
| `next.config.ts` | wrap the export with `withNextIntl(...)` (`createNextIntlPlugin("./src/i18n/request.ts")`) and add `@igrp/framework-next/i18n` and `@igrp/framework-next/i18n/client` to `optimizePackageImports`; keep your own config around that |
| `src/igrp.template.config.ts` | add `i18n` (from `@/i18n`) to the `igrpBuildConfig({ ... })` call |
| `src/middleware.ts` | comment only; safe to skip if you customised the middleware |
| `.env.example` | copy the `IGRP_FORMAT_LOCALES` block into your own example |
| `src/app/(igrp)/layout.tsx`, `src/app/(auth)/login/page.tsx` | re-apply your own slots and layout around the `IGRPLocaleSwitcher` lines |
| `src/app/global-error.tsx`, `src/app/error.tsx`, `src/app/(igrp)/error.tsx`, `src/app/(auth)/error.tsx` | swap `@/config/error-messages` for `resolvePublicErrorCopy` from `@/lib/error-copy`; platform codes need no resolver at all |
| `src/components/home-overview.tsx`, `src/app/(igrp)/page.tsx` | if you already replaced the home page, drop these two steps from your apply or restore your files afterwards |
| `src/config/login.ts` | keep your texts; just do not set `loginButton` (the chrome catalog provides it per language) |

- Your own feature strings are untouched. Migrate a folder at a time and add it to `lint:i18n` when done.
- `IGRP_FORMAT_LOCALES` must be region-qualified (`pt-PT`, never `pt`): a bare language makes every request fail with a generic error page; the server log names `IGRP_I18N_CONFIG_INVALID`.
