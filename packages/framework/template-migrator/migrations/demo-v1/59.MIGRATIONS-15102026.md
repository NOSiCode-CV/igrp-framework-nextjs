# 59 — Session store required for multi-replica and shared-domain deployments

## What changed

| File | Change |
| --- | --- |
| `.env.example` | `IGRP_SESSION_STORE_URL` documented as **required** with more than one replica or on a shared domain; `IGRP_SESSION_MAX_AGE=28800` recommended |

Documentation only: no code, environment value or dependency changes.

## Why

- **`IGRP_SESSION_STORE_URL`.** Without a store, the refresh token lives in the
  session cookie. With several replicas, two of them can refresh the same
  session at the same moment with the same refresh token. IGRP Access
  Management keeps a permanent record of every rotated-out refresh token and
  treats a second use as theft: it revokes the session. On a domain shared with
  other IGRP apps, the cookies also overflow proxy header limits. The framework
  now logs a warning once, in production, when it writes a session without a
  store.
- **`IGRP_SESSION_MAX_AGE=28800`.** Access Management ends every session after
  8 h. Without this value the session cookie, and the session-store entry,
  default to NextAuth's 30 days and linger long after the session is gone.

## What to do

- More than one replica, or apps sharing a domain: set
  `IGRP_SESSION_STORE_URL` (see migration 56).
- Every deployment against IGRP Access Management: set
  `IGRP_SESSION_MAX_AGE=28800`.
