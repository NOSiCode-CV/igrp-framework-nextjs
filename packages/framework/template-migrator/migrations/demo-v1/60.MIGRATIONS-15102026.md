# 60 — Organization branding; preset themes removed

## What changed

| File | Change |
| --- | --- |
| `.env.example` | New `IGRP_BRANDING_ENABLED` (empty = off) |
| `src/igrp.template.config.ts` | Passes `branding: { enabled: process.env.IGRP_BRANDING_ENABLED === "true" }` |
| `src/app/layout.tsx` | Static `metadata` becomes `generateMetadata`; the favicon follows the organization Brand via `igrpBrandingMetadata` |
| `src/actions/igrp/layout.ts` | `getTheme()` and the `igrp_active_theme` cookie read are gone; `configLayout()` returns `{ session }` |
| `src/styles/globals.css` | No longer imports `themes.css`; keeps its `body` overscroll rule and `--header-height`; the commented sidebar-override block is removed |
| `src/lib/fonts.ts` | Comment only: `theme-mono` no longer exists |
| `src/styles/themes.css` | Deleted |

## Why

- The framework can now load the organization Brand (colour tokens and logos)
  that administrators set in the Application Center, and apply it before first
  paint. It is off unless `IGRP_BRANDING_ENABLED=true`; off means no request and
  no change to the page.
- The preset themes (`theme-blue`, `theme-green`, …, `theme-scaled`) and the
  theme selector were removed from `@igrp/framework-next-ui`. Nothing sets the
  `theme-*` classes any more, so their CSS was dead.

## What to do

- To use the organization Brand, set `IGRP_BRANDING_ENABLED=true` in `.env`.
  Leave it empty or `false` to keep the design-system defaults.
- Requires the framework release that ships `igrpBrandingMetadata` and
  `igrpResolveRequestBranding` in `@igrp/framework-next`.

## ⚠️ If you customised these files

- `themes.css`: if you defined your own colours in a `.theme-*` block, move
  them to `:root` / `.dark` in `globals.css` before applying, or set them as the
  organization Brand in the Application Center.
- `globals.css`, `layout.tsx`, `igrp.template.config.ts`, `actions/igrp/layout.ts`
  and `.env.example` are replaced. Re-apply your additions on top of the new
  files. Your `.env` is not touched.
