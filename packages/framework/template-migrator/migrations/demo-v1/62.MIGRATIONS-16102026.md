# 62 — Time zone for dates and times (`IGRP_TIME_ZONE`)

## What changed

| File | Change |
| --- | --- |
| `src/i18n/index.ts` | passes `timeZone: process.env.IGRP_TIME_ZONE \|\| "Atlantic/Cape_Verde"` to `igrpDefineI18n` |
| `.env.example` | documents `IGRP_TIME_ZONE` under Localisation |

## Why

Without a time zone, next-intl formats dates in each runtime's own zone and logs
`ENVIRONMENT_FALLBACK: The timeZone parameter wasn't provided`. A server in UTC
and a browser in Praia then render different times for the same value, which
also causes hydration mismatches. The default, `Atlantic/Cape_Verde`, matches the
default format locale `pt-CV`.

## What to do

Deployments outside Cape Verde: set `IGRP_TIME_ZONE` to an IANA zone name
(`Europe/Lisbon`, `Africa/Luanda`). The name isn't checked at startup: a typo
fails the first time a date is formatted.

Both are replaced. Re-apply your changes on top. Your `.env` is not touched.
