# 63 — Login, 404, page title and auth screens follow the language

## What changed

| File | Change |
| --- | --- |
| `src/config/login.ts` | `welcome`, `description`, `copyright` and the carousel copy removed; exports `carouselImages` (one image per slide) |
| `src/app/(auth)/login/page.tsx` | builds the form texts and the carousel from the new `login` namespace |
| `src/app/(auth)/login/logout-completion.tsx`, `silent-sign-in.tsx`, `src/app/(auth)/logout/page.tsx` | loading text from `auth.signingOut` / `auth.pleaseWait` |
| `src/app/not-found.tsx` | `generateMetadata`: title from `errors.status.404`, description from `notFound.description` (drops the Brazilian phrasing) |
| `src/app/layout.tsx` | page title and description from `app.title` |
| `src/i18n/messages/{pt,en,fr}.json` | new `login`, `notFound` and `auth` namespaces |
| `src/components/home-overview.tsx` | example placeholders in English (`<module>`, `<route>`, `<permission>`) |
| `src/app/global-error.tsx` | comment only: it formats with the default format locales because env isn't readable there |
| `docs/I18N.md` | the check's real scope; plural messages always include `=0` |

## Manual steps

1. `package.json` scripts: append `src/config "src/app/(auth)" src/app/not-found.tsx src/app/layout.tsx` to `igrp-i18n check-literals` in `lint:i18n`:
   `"lint:i18n": "igrp-i18n check-catalogs src/i18n/messages --default pt && igrp-i18n check-literals src/components src/i18n \"src/app/(igrp)/page.tsx\" src/config \"src/app/(auth)\" src/app/not-found.tsx src/app/layout.tsx"`
2. Optional, if you build with `docker/development/Dockerfile`: its comment above `next build` now says `pnpm build` also runs `lint:i18n`. Nothing to change in the build itself.

No `deps.bump`: the framework fixes this migration goes with are not released yet. Add one with the registry versions once they are.

## Why

A user who picked French on `/login` still saw the Portuguese heading and the English carousel, and the browser tab and the 404 title stayed in Portuguese. Every one of these strings now comes from the app's messages. Plural messages need `=0` because next-intl gets the bare base locale and `pt` uses Brazilian plural rules, where 0 is `one`.
