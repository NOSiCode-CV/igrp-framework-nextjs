# 64 — Deployment region on the global error page

## What changed

| File | Change |
| --- | --- |
| `src/app/global-error.tsx` | `<html lang>` uses `igrpLastFormatLocale()` from `@igrp/framework-next/i18n/client`, the format locale the intl provider last rendered with; the `IGRP_LOCALE` cookie stays the fallback |

## Why

`global-error.tsx` replaces the root layout, so it renders outside every provider
and can't read `IGRP_FORMAT_LOCALES`, a server env var. It used the default
regions, so a `pt-PT` deployment got `<html lang="pt-CV">` on that page. The
provider now records its format locale in client module state, which outlives
the root layout it replaces. When the root layout failed on the server before the
provider ever mounted, the page still falls back to the cookie and the default
regions.

## Manual steps

1. `package.json`: `@igrp/framework-next` must be a release that exports
   `igrpLastFormatLocale` from `./i18n/client` (the first release after
   `0.2.0-beta.9`). This migration has no `deps.bump`: that release isn't
   published yet.

## ⚠️ If you customised `src/app/global-error.tsx`

It is replaced. Re-apply your changes on top: import `igrpLastFormatLocale` and
return it, when set, before reading the cookie.
