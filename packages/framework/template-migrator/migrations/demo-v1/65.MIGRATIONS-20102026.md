# 65 — Framework dependency resync (0.2.0-beta.9)

## What changed

| Dependency | From | To |
| --- | --- | --- |
| `@igrp/framework-next` | `0.2.0-beta.8` | `0.2.0-beta.9` |
| `@igrp/framework-next-auth` | `0.2.0-beta.7` | `0.2.0-beta.8` |
| `@igrp/framework-next-types` | `0.2.0-beta.7` | `0.2.0-beta.8` |
| `@igrp/framework-next-ui` | `0.2.0-beta.8` | `0.2.0-beta.9` |
| `@igrp/igrp-framework-react-design-system` | `0.2.0-beta.5` | `0.2.0-beta.6` |
| `@igrp/framework-next-i18n` | (declared by hand in 58) | `0.2.0-beta.1` |

## Why

The framework packages were released after migration 61 pinned them, so a
migrated app stayed one release behind a fresh template. `@igrp/framework-next-i18n`
is pinned for the first time; migration 58 only asked you to add it. A
`deps.bump` changes only dependencies your `package.json` already declares, and
prints the ones it skipped.

These are the latest published versions. Migrations 63 and 64 use framework
fixes that are not published yet (64's `global-error.tsx` imports
`igrpLastFormatLocale`, which `0.2.0-beta.9` doesn't export). The migration
published with that release bumps the framework again; until then, don't apply
64 to an app pinned to `0.2.0-beta.9`.

## After migrating

Run `pnpm install`.
