# 67 — Framework release 0.2.0-beta.10

## What changed

| Dependency | From | To |
| --- | --- | --- |
| `@igrp/framework-next` | `0.2.0-beta.9` | `0.2.0-beta.10` |
| `@igrp/framework-next-ui` | `0.2.0-beta.9` | `0.2.0-beta.10` |
| `@igrp/igrp-framework-react-design-system` | `0.2.0-beta.6` | `0.2.0-beta.7` |
| `@igrp/framework-next-i18n` | `0.2.0-beta.1` | `0.2.0-beta.2` |

`@igrp/framework-next-auth` and `@igrp/framework-next-types` are unchanged (`0.2.0-beta.8`).

## Why

This is the release that migrations 63 and 64 rely on. 64's `global-error.tsx`
imports `igrpLastFormatLocale` from `@igrp/framework-next/i18n/client`, which
`0.2.0-beta.9` doesn't export. It also ships the i18n review fixes: date-only
values keep their calendar day, server actions send `Accept-Language` and return
translatable error `code`s, the remaining design-system and chrome strings come
from the catalogs, and `igrp-i18n check-literals` is stricter (see each
package's CHANGELOG).

## After migrating

Run `pnpm install`. If you run `igrp-i18n check-literals` over more folders than
the template does, it now also reports literals inside conditionals and
hardcoded `Intl` locales; mark a literal that is not language with an
`igrp-i18n-ignore` comment.
