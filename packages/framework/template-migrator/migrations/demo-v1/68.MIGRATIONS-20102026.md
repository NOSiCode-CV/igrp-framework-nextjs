# 68 — Faster first compile in `next dev`: one chunk for all lucide icons

## What changed

| File | Change |
| --- | --- |
| `next.config.ts` | exports a function of the Next phase; under `next dev` the `lucide-react/dynamicIconImports` alias points at a generated map that serves every icon from one lazy chunk; lucide is resolved from the design system's real location |

## Why

lucide's `dynamicIconImports` has one `import()` per icon (about 1,950).
Turbopack turns each into its own client and server chunk with a sourcemap,
which made the first `next dev` compile take minutes on Windows. In dev the
config now writes `node_modules/.cache/lucide-dev-icons/` on every start: one
module re-exporting all icons, and a map with the same keys whose loaders all
import that module. `IGRPIcon` sees the same `{ default, __iconNode }` shape.
`next build` keeps the real per-icon map, so production bundles are unchanged.

The old alias walked `../../lucide-react` from the design system's real path,
which only exists in a pnpm-store layout. It is now resolved with
`createRequire` from the design system's `package.json`.

## After migrating

Nothing to run. If a lucide upgrade changes the format of
`dist/esm/dynamicIconImports.js`, `next dev` stops with an error that names
`writeDevLucideIconMap` in `next.config.ts`.

## ⚠️ If you customised `next.config.ts`

This step replaces the whole file. Re-apply your own settings inside
`nextConfig(phase)`, and keep the default export as
`(phase) => withNextIntl(nextConfig(phase))`. To take only this change, copy
`lucideDir`, `toAliasPath` and `writeDevLucideIconMap` and the new
`resolveAlias` value into your file.
