# 69 — Framework release 0.2.0-beta.11

## What changed

| Dependency | From | To |
| --- | --- | --- |
| `@igrp/framework-next` | `0.2.0-beta.10` | `0.2.0-beta.11` |
| `@igrp/framework-next-ui` | `0.2.0-beta.10` | `0.2.0-beta.11` |
| `@igrp/framework-next-i18n` | `0.2.0-beta.2` | `0.2.0-beta.3` |

`@igrp/igrp-framework-react-design-system` (`0.2.0-beta.7`), `@igrp/framework-next-auth` and
`@igrp/framework-next-types` (`0.2.0-beta.8`) are unchanged.

## Why

- `igrp-i18n check-catalogs` now fails when a locale lacks a key the default
  locale has.
- Both locale cookie writers set `Secure` from `x-forwarded-proto`, so the
  cookie is kept behind a TLS-terminating proxy.
- The chrome has copy for the `IGRP_I18N_CONFIG_INVALID` error.
- `docs/I18N.md` describes the session-first locale flow (see
  "Session-first").

## After migrating

Run `pnpm install`.

`check-catalogs` fails on missing keys. While a locale is incomplete, add
`--allow-missing` to that command in `lint:i18n`:
`igrp-i18n check-catalogs src/i18n/messages --default pt --allow-missing`.

Manual step (the migrator has no `scripts` step): in `package.json`, append
these four paths to the end of the `check-literals` list in `lint:i18n`:

```
src/app/global-error.tsx src/app/error.tsx "src/app/(igrp)/error.tsx" "src/app/(igrp)/layout.tsx"
```
