# 71 — Auth-bypass production guard

## What changed

| File | Change |
| --- | --- |
| `src/instrumentation.ts` | calls the auth-bypass guard first inside the `NEXT_RUNTIME === "nodejs"` block |
| `.env.example` | documents `IGRP_ALLOW_AUTH_BYPASS_IN_PRODUCTION` (empty) |
| `docker/development/.env.development` | opts in with `IGRP_ALLOW_AUTH_BYPASS_IN_PRODUCTION=true` |

| Dependency | From | To |
| --- | --- | --- |
| `@igrp/framework-next` | `0.2.0-beta.12` | `0.2.0-beta.13` |

## Why

A production deploy with preview mode left on (`IGRP_PREVIEW_MODE=true` or
`AUTH_PROVIDER=none`) served every visitor as super-admin. Now `register()`
throws when the bypass is on in a production build without the opt-in. Next
logs `[igrp-auth-bypass]...` and answers every request with 500; the process
does not exit.

`@igrp/framework-next` also changes `isIgrpAuthBypass()` to strip quotes, so an
app with a literally quoted `AUTH_PROVIDER="none"` now gets the super-admin mock
for permission checks.

## After migrating

Run `pnpm install`.

If your real deploys set `IGRP_PREVIEW_MODE` or `AUTH_PROVIDER=none` on purpose,
add `IGRP_ALLOW_AUTH_BYPASS_IN_PRODUCTION=true` there.

`env.add` creates `docker/development/.env.development` if the app had deleted
that folder.

If you edited `src/instrumentation.ts`, merge by hand: the replace overwrites
it. Re-apply your edits around the two-line dynamic import and call of the
guard, which sits first inside the `NEXT_RUNTIME === "nodejs"` block.
