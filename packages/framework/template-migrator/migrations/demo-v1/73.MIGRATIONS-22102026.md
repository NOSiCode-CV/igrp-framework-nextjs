# 73 — Session-first switcher: check the session update

## What changed

`docs/I18N.md` ("Session-first") now shows a switcher wrapper that checks the
result of `update({ locale })` and throws when the session was not updated.

## Why

next-auth's `update()` resolves `null` instead of rejecting when the session
can't be written (for example a session-store timeout). The old snippet ignored
that, so the language was saved to the profile while the session kept the old
one: the page reverted on the next request and the new language appeared "by
itself" at the next sign-in. From `@igrp/framework-next` 0.2.0-beta.13 the
switcher rolls a persisted change back when `onChanged` throws, so throwing on a
failed update is all an app has to do.

## After migrating

Cookie-first apps: nothing to do. Session-first apps: update your switcher
wrapper to the snippet in `docs/I18N.md`.
