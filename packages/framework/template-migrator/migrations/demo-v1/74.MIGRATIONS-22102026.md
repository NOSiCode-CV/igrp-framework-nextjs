# 74 — framework-next 0.2.0-beta.14, i18n dependencies

## What changed

| Dependency | From | To |
| --- | --- | --- |
| `@igrp/framework-next` | `0.2.0-beta.13` | `0.2.0-beta.14` |
| `next-intl` | not declared | `^4.14.0` (added only if missing) |
| `@igrp/framework-next-i18n` (dev) | not declared | `0.2.0-beta.3` (added only if missing) |

## Why

`@igrp/framework-next` 0.2.0-beta.14: when `onChanged` fails after a persisted
(session-first) locale change, the switcher rolls the profile and cookie back to
the previous locale instead of refreshing into the old session locale.

Migration 58 listed `next-intl` and `@igrp/framework-next-i18n` as manual steps.
An app that skipped them fails at `createNextIntlPlugin` in `next.config.ts`
(pnpm does not let the app import `next-intl` through `@igrp/framework-next`),
and `pnpm lint:i18n` has no `igrp-i18n` command. Migration 69's bump of
`@igrp/framework-next-i18n` also skipped those apps.

An app that already declares either dependency keeps its own range.

## After migrating

Run `pnpm install`.
