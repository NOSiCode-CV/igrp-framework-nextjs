# 75 — Multi-app auth sessions

## What changed

| File | Change |
| --- | --- |
| `src/lib/logout-pending.ts` | marker cookies take `Secure` from the page protocol |
| `src/lib/silent-sso.ts` | marker cookies take `Secure` from the page protocol |
| `src/app/(auth)/login/page.tsx` | handles `?reason=session_ended` |
| `src/app/(auth)/login/session-ended-completion.tsx` | new — clears the local session, then returns to `/login` |
| `src/app/(auth)/login/logout-completion.tsx` | writes the host-wide logout signal after an explicit logout |
| `src/app/(auth)/logout/page.tsx` | calls `markHostLogout` before leaving |
| `src/actions/igrp/auth.ts` | new `markHostLogout` server action, writes `igrp.logout-at` |
| `src/middleware.ts` | redirects to `/login?reason=session_ended` when another app on the host logged out |
| `src/app/forbidden.tsx` | new — renders the forbidden page for a 403 thrown by the `(igrp)` layout |

No dependency changes. This migration depends on framework changes:
`@igrp/framework-next-auth` (`authTime`, `isEndedByHostLogout`,
`HOST_LOGOUT_COOKIE`) and `@igrp/framework-next` (401/403 handling).

## Why

Several apps can share one host: App Center at `/` and other apps under
`/apps/*`. Each has its own session cookie, so the apps did not agree on when a
session ended.

- The marker cookies (logout-pending, silent SSO) were lost on production
  builds served over plain HTTP, because `Secure` was always set. They now
  take `Secure` from the page protocol.
- When Access Management answers 401, the app now ends its local session
  through `/login?reason=session_ended`. A 403 renders the forbidden page.
- An explicit logout in one app writes `igrp.logout-at`. The other apps on the
  host see it and end their sessions in the same browser.

## After migrating

Update `@igrp/framework-next-auth` and `@igrp/framework-next` to the versions
that ship the changes above, then run `pnpm install`.

`src/app/(auth)/login/session-ended-completion.tsx` and `src/app/forbidden.tsx`
are new files. If your app already has its own file at either path, the
migration replaces it: copy yours aside before migrating, then merge it back by
hand.

If you customised `login/page.tsx`, `logout-completion.tsx`, `logout/page.tsx`,
`middleware.ts`, `src/lib/silent-sso.ts`, `src/lib/logout-pending.ts` or
`src/actions/igrp/auth.ts`, re-apply your changes on top of the new versions.
