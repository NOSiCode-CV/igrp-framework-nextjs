# 81 — Logout ends the session even if the IdP never redirects back; linear public-path check

## What changed

| File | Change |
| --- | --- |
| `src/app/(auth)/logout/page.tsx` | On the IdP path, `markHostLogout()` now runs before the end-session POST, not only after the IdP redirects back. |
| `src/middleware.ts` | `isPublicPath` tests its file-extension regex on the last path segment only. |

## Why

- **Logout.** On the IdP path, the local session stayed alive behind a 5-minute `logout_pending` cookie. If the IdP never sent the browser back (an unregistered `post_logout_redirect_uri`, an IdP error page, or a closed tab), that cookie expired and the old session worked again: the next person on a shared machine was signed in as the previous user. The `igrp.logout-at` cookie is now written before the browser leaves, so middleware ends that session whether or not the browser comes back.
- **Middleware.** `/\.[^/]+$/` ran on the whole request path before any auth check. A path with a long run of dots followed by `/` made it backtrack quadratically, so unauthenticated requests could burn CPU. The same paths are public as before.

## Behaviour changes to check

- **Co-hosted apps** see the host-logout signal when the user clicks Logout, a moment before the IdP round-trip finishes. If the round-trip is abandoned, their sessions now end too.
- **Slow logout:** the IdP POST waits for one extra server action. If the end-session lookup plus that action take longer than the 8-second watchdog, the page falls back to `/login` and ends the local session without ending the IdP session, the same as an end-session lookup timeout.

## After migrating

Nothing to do. If you changed either file, merge the change by hand: in `logout/page.tsx`, call `markLogoutPending()` and then `await markHostLogout()` before `setEndSessionPost(...)` in the `endSessionUrl` branch.
