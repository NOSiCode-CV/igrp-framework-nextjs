# 85 — Dotted routes go through the auth check; CSP reports are collected

## What changed

| File | Change |
| --- | --- |
| `src/middleware.ts` | `isPublicPath` treated any URL whose last segment had a dot (`/users/john.doe`, `/api/users/john.doe`) as a static file and skipped the token check. It now skips only the static-asset extensions the matcher already lists. The CSP gets a `report-uri` pointing at `/api/csp-report`, which is public. |
| `src/lib/utilities.ts` | `isPreviewMode` and `isAuthDisabled` trim again after stripping quotes, so `" true"` is read the same way the framework reads it. |
| `src/app/api/csp-report/route.ts` | New. Logs CSP violation reports (bodies over 8 KB are refused). |

## Why

- **Dotted routes:** an API route with a dotted id was reachable without a session, and a dotted page relied only on the `(igrp)` layout check.
- **Env parsing:** with `IGRP_PREVIEW_MODE='" true"'` the template kept auth on while the framework granted super-admin claims.
- **CSP reports:** the policy is report-only and had no report endpoint, so violations only showed in the user's browser console and nobody could tell when it was safe to enforce.

## Behaviour changes to check

- Requests to dotted routes without a session now redirect to `/login` (pages) or are refused (API), as other protected routes are.
- Server logs get one `[csp-report]` line per violation. Once they stop, switch the header in `middleware.ts` from `Content-Security-Policy-Report-Only` to `Content-Security-Policy`.

## After migrating

Nothing to do. If you changed either file, merge by hand:

- `middleware.ts`: replace the `/\.[^/]+$/` test in `isPublicPath` with the matcher's extension list (`STATIC_ASSET_RE`), add `report-uri <basePath>/api/csp-report` to the policy, and add `/api/csp-report` to `PUBLIC_PATHS`.
- `lib/utilities.ts`: add `?.trim()` after the quote-stripping `replace` in both functions.
