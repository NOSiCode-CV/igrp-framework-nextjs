No template files change. Each package's CHANGELOG lists its fixes; the ones an app can notice are below.

## Behaviour changes to check

- **Cleared form fields.** `IGRPInputNumber` and the date pickers write `null` when cleared, so their schemas need `.nullable()` (or `.nullish()`). Don't validate a required number with `z.coerce.number()`: it turns `null` into `0`. Phone and URL inputs clear to `""`, so `z.string()` schemas keep working.
- **Removed exports.** `IGRPLayout` (use `IGRPLayoutFull`), `igrpResetAccessClient`, `revalidateMenusAction`, `revalidateAppsAction`, `introspectOidcToken`, `formatDateRange`, `parseStringToRange`, `IGRPCellType` and `IGRPCellConfig`. Nothing in the template uses them.
- **Auth bypass in production.** `igrpGetClaims` and the Server Action session gate now refuse `IGRP_PREVIEW_MODE=true` or `AUTH_PROVIDER=none` in a production build unless `IGRP_ALLOW_AUTH_BYPASS_IN_PRODUCTION=true`, even without the `instrumentation.ts` guard.
- **Sidebar.** `IGRPLayoutFull` restores the collapsed or expanded state from the `sidebar_state` cookie. The cookie path is `/`, so apps on one domain share it.
- **`igrp-i18n`.** The CLI runs again: `0.2.0-beta.3` shipped `.mjs` files its `bin` did not point at, so `pnpm lint:i18n` (and `build`) failed with "Cannot find module".

## After migrating

Run `pnpm install`. If you validate cleared numbers or dates, update those schemas as above.
