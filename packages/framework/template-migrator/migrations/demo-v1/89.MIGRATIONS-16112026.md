# 89 — Another site can no longer sign users out through /logout

## What changed

| File | Change |
| --- | --- |
| `src/app/(auth)/logout/layout.tsx` | New. Decides whether `/logout` starts the logout by itself or asks first. |
| `src/app/(auth)/logout/logout-confirm.tsx` | New. Shows a "Sign out" button until the user confirms, then mounts the unchanged logout page. |
| `src/i18n/messages/{pt,en,fr}.json` | Adds `auth.confirmSignOut` and `auth.signOut`. |

## Why

`/logout` is a public GET whose page starts the full logout on mount: it ends the IdP session and writes the host-wide `igrp.logout-at` cookie, which ends every co-hosted app's session. Any site could navigate a signed-in user there and sign them out everywhere, as often as it liked.

## Behaviour changes to check

The logout starts by itself when the request came from the app:

- `Sec-Fetch-Site: same-origin`: the menu's Sign out link (including open in new tab), `IGRPSessionWatcher`, and the `onSessionExpired` redirect during navigation.
- No `Sec-Fetch-Site` header (plain-HTTP hosts other than localhost, older browsers): a Referer from the same host.
- `Sec-Fetch-Site: none` (typed URL, bookmark), or no header and no Referer: only when the session is already expired or its refresh failed, which covers the `onSessionExpired` redirect on a full page load.

Everything else shows a confirm screen with one Sign out button: links from other sites or sibling subdomains, and a typed or bookmarked `/logout` while the session is still valid. If another app on a different origin links to your `/logout`, its users now confirm once.

## After migrating

Nothing to do. If you changed the message catalogs, add the two `auth` keys by hand instead of taking the replaced files:

- pt: `"confirmSignOut": "Pretende terminar a sessão?"`, `"signOut": "Terminar sessão"`
- en: `"confirmSignOut": "Do you want to sign out?"`, `"signOut": "Sign out"`
- fr: `"confirmSignOut": "Voulez-vous vous déconnecter ?"`, `"signOut": "Se déconnecter"`
