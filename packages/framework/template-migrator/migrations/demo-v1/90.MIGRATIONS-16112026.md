# 90 — Switching back to the tab no longer hits /api/auth/session every time

## What changed

| File | Change |
| --- | --- |
| `src/lib/config/get-session-args.ts` | `refetchOnWindowFocus` is now `false` outside preview mode. Comments updated. |

## Why

next-auth's `refetchOnWindowFocus` sent `GET /api/auth/session` on every tab switch, with no throttle. Each request goes through middleware, decrypts the session cookie and runs the `jwt` callback (and reads Redis when the session store is on). `IGRPSessionWatcher` in `@igrp/framework-next-ui` 0.2.0-beta.22 now refreshes the session itself when the tab becomes visible and the session is more than 60 seconds old, so the next-auth refetch only duplicated it.

## Behaviour changes to check

- Needs `@igrp/framework-next-ui` 0.2.0-beta.22 or later. With an older version, a returning tab only refreshes on the 600-second backstop or on navigation.
- The watcher's focus refresh only runs for sessions that carry `expiresAt`. The IGRP provider always sets it. If you added a custom provider whose sessions have no `expiresAt`, set `refetchOnWindowFocus` back to `true`.

## After migrating

Nothing to do. If you changed this file, set `refetchOnWindowFocus: false` in the non-bypass branch by hand.
