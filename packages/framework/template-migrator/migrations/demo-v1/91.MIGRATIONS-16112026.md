# 91 — The framework fills the command palette; layout data picked once

## What changed

| File | Change |
| --- | --- |
| `src/app/(igrp)/layout.tsx` | The header is passed as `header={<IGRPLayoutHeader config slots />}`. The `search` slot, its `<Suspense>` and `AppSearchSlot` are gone; only the locale switcher slot remains. |
| `src/lib/header-search.ts` | Deleted. |
| `src/components/app-search.tsx` | Deleted. |
| `src/igrp.template.config.ts` | Two module-level layout data sources, `liveLayoutData` and `previewLayoutData`, picked once with `bypass ? previewLayoutData : liveLayoutData`. The preview one adds `getMenus`, `getUser` and `getApps` with the `src/temp` mocks, replacing the per-field `bypass ? mock : undefined` ternaries. The no-op `defaultOpen` is dropped. |
| `src/components/home-overview.tsx` | One `status` (`error` / `preview` / `ok`) computed once; colours come from `Record<HomeLayerState, …>` maps and text from `t(\`intro.${status}\`)`. |
| `src/i18n/messages/{pt,en,fr}.json` | `home.intro.failing`, `home.status.failing` and `home.requestPath.failing` renamed to `…error`. |
| `docs/HEADER_SLOTS.md`, `README.md` | Rewritten for `IGRPLayoutHeader`, slots that always render, the filled palette, page breadcrumbs and parts composition. |

## Why

`@igrp/framework-next` now builds the header palette's commands on the server from the same menu fetch the sidebar uses, so the template's own copy (server data in `header-search.ts`, client handlers in `app-search.tsx`) only duplicated it. The new `layoutData.getMenus/getUser/getApps` methods let the template hand the framework its mock data directly instead of branching each field on `isAuthBypass()`.

## Behaviour changes to check

- Needs `@igrp/framework-next` 0.2.0-beta.24 or later, with the `@igrp/framework-next-ui` and `@igrp/framework-next-types` released alongside it (for `IGRPLayoutHeader`, the filled palette and the `layoutData` methods).
- A supplied header slot now renders even when its `show*` flag is off. Before, `showSearch: false` with a `search` slot rendered nothing.
- In preview mode the header user comes from `getUser()`, so `getHeaderData()` no longer returns `user`.
- If you customised `src/igrp.template.config.ts`, this step replaces it. Merge by hand: move your header and sidebar fields into `liveLayoutData`, keep any mock overrides in `previewLayoutData` (`getMenus`, `getUser`, `getApps`), and set `layoutData: bypass ? previewLayoutData : liveLayoutData`. The rest of the file (`apiManagementConfig`, `toasterConfig`, `sessionArgs`, …) is unchanged.
- If you customised the palette in `app-search.tsx` (extra commands, different grouping), keep the two files and pass `slots={{ search: … }}` to `IGRPLayoutHeader` as before; the framework then builds no menu commands.
- If you added other slots in `src/app/(igrp)/layout.tsx`, move them into `slots` on `IGRPLayoutHeader`. `headerSlots` on `IGRPLayoutFull` still works but is deprecated.
- If you use the `home.*.failing` message keys elsewhere, rename them to `…error`.

## After migrating

Run `pnpm lint:i18n` and `tsc --noEmit`. Open the app with `IGRP_PREVIEW_MODE=true` and press `Ctrl+K`: the palette lists the mock menus.
