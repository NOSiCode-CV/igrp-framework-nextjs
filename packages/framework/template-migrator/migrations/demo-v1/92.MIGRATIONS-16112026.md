# 92 — lucide-react 1.x in dev, and tests for the auth bypass paths

## What changed

| File | Change |
| --- | --- |
| `next.config.ts` | The dev-only icon map reads lucide's `dist/esm/dynamicIconImports.js` (0.x) or `.mjs` (1.x), whichever exists. Before, `next dev` failed with ENOENT on lucide-react 1.x. |
| `docs/HEADER_SLOTS.md` | A server module can build palette items with `href` instead of an `onSelect` callback. |
| `package.json` | `vitest` 5.1.0 added to `devDependencies`. |
| `vitest.config.mts` | New. Node environment, `@/` alias, tests under `src/**/__tests__`. |
| `src/__tests__/auth-bypass.test.ts` | New. Runs the middleware with bypass on (`IGRP_PREVIEW_MODE=true` and `AUTH_PROVIDER=none`) and off, and checks `isAuthBypass()` and `getSessionArgs()` in both. |
| `src/lib/__tests__/sanitize-callback-url.test.ts` | New. Open-redirect and login-loop cases for `sanitizeCallbackUrl`. |

## Why

The design system and `@igrp/framework-next-ui` now accept lucide-react `^0.577.0 || ^1.0.0`, so an app can move to lucide 1.x. The template's dev icon map was the one piece that only knew the 0.x file layout.

`@igrp/framework-next-ui`'s `IGRPCommandItem` now takes `href` as an alternative to `onSelect`, which the docs said a server module could not build.

Every auth-aware path must work with the bypass on and off, and nothing checked that. These tests run the real middleware against both.

## Manual step

Add a `test` script to `package.json`:

```json
"test": "vitest run"
```

## Behaviour changes to check

- If you changed `next.config.ts`, this step replaces it. The only change is in `writeDevLucideIconMap`; merge it by hand.
- If your middleware differs from the template's (extra public paths, a different login URL), adjust `src/__tests__/auth-bypass.test.ts` to match.
- lucide-react 1.x removed 18 brand icons (`Github`, `Facebook`, `Slack`, …). A menu that names one renders the unknown-icon glyph; pick another icon.

## After migrating

Run `pnpm install` and `pnpm test`.
