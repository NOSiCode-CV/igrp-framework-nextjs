# 93 — Every page has its own title; the login page has a main landmark

## What changed

| File | Change |
| --- | --- |
| `src/app/layout.tsx` | `title` is `{ default, template: "%s · <app title>" }`, so a page's own title is followed by the app name. |
| `src/app/(auth)/login/page.tsx` | `generateMetadata` sets the title from `login.pageTitle`, and the page's root `<section>` is now `<main>`. |
| `src/app/(auth)/logout/layout.tsx` | `generateMetadata` sets the title from `auth.signOut` (the page itself is a client component). |
| `src/app/forbidden.tsx`, `src/app/(igrp)/forbidden.tsx` | `generateMetadata` sets the title from `errors.status.403`. |
| `src/i18n/messages/{pt,en,fr}.json` | New `login.pageTitle`. |

## Why

Every page had the same `<title>`, so tabs and history were indistinguishable and Next's route announcer read the same text on every navigation (WCAG 2.4.2). The global error page gets its title from `@igrp/framework-next-ui`'s `IGRPGlobalError`.

## Behaviour changes to check

- Give your own pages a title: `export const metadata = { title: "…" }` or `generateMetadata` with a translated string. It renders as "<page> · <app title>".
- If you customised the message catalogs, these steps replace them. Merge by hand: add `"pageTitle"` under `login` in each language.
- If you customised the login page, the logout layout or the forbidden pages, merge the `generateMetadata` additions (and the login `<main>`) by hand.

## After migrating

Run `pnpm lint:i18n` and `tsc --noEmit`, then open `/login` and a forbidden page and check the browser tab title.
