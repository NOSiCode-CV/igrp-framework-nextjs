# 98 — Middleware auth decision and auth-bypass predicate from next-auth

## What changed

| File | Change |
| --- | --- |
| `src/middleware.ts` | The auth decision (bypass, public paths, `logout_pending` backstop, token, host logout, `callbackUrl`) is `igrpMiddlewareDecision` from `@igrp/framework-next-auth/middleware`. The file keeps the CSP, security headers, `x-current-path` / `x-nonce`, the stale-cookie sweep and the literal `config`. Extra public paths (`/api/health`, `/api/csp-report`) are passed as `publicPaths`. |
| `src/lib/utilities.ts` | `isPreviewMode`, `isAuthDisabled` and `isAuthBypass` delegate to `@igrp/framework-next-auth/providers`; `sanitizeCallbackUrl` is re-exported from `@igrp/framework-next-auth/sanitize`. |

## Why

The bypass predicate, the callback sanitizer and the middleware's auth rules each had a copy in the template and one in the framework. One definition means the middleware, server actions and session callbacks cannot disagree about whether auth is on.

## Behaviour changes to check

None intended: preview mode and `AUTH_PROVIDER=none` still redirect `/login`, `/logout` and `/api/auth/*` to `/` and let every other path through. If you added public paths to `PUBLIC_PATHS` or changed `isPublicPath`, put the exact paths in the `publicPaths` array; prefixes other than `/login/`, `/logout/` and `/api/auth/` need their own check before the decision.

## After migrating

Needs `@igrp/framework-next-auth` `0.2.0-beta.12` or later.
