# 99 — Sidebar user menu reads the same URLs as the header

## What changed

| File | Change |
| --- | --- |
| `src/igrp.template.config.ts` | `getSidebarData` sets `profileUrl`, `notificationsUrl` and `settingsUrl` from `NEXT_PUBLIC_IGRP_PROFILE_URL`, `NEXT_PUBLIC_IGRP_NOTIFICATION_URL` and `NEXT_PUBLIC_IGRP_SETTINGS_URL`, and sets the new `showProfile` and `showSettings` flags to `true`. |

## Why

Only `getHeaderData` read these env vars. The sidebar user menu fell back to `/profile` and `/settings`, which `next/link` prefixes with the basePath, so the sidebar linked to `/apps/<basePath>/settings` while the header linked to the configured URL.

## Behaviour changes to check

The sidebar Profile, Notifications and Settings entries now go where the header ones go. To hide an entry from the sidebar user menu, set `showProfile`, `showSettings` or `showNotifications` to `false` in `getSidebarData`.

If you changed `igrp.template.config.ts`, copy only the new `getSidebarData` fields into your file.

## After migrating

Needs `@igrp/framework-next-types` and `@igrp/framework-next-ui` with the `showProfile` / `showSettings` sidebar fields.
