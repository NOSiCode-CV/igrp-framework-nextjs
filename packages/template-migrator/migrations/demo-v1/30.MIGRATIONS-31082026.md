# 30 — Resync to beta.166 + peer-dependency catch-up

A **dependency-only** migration. It touches no source files; it exists so that
an app upgraded through `igrp-migrate apply` ends up on the same dependency set
a freshly-scaffolded app gets from the template zip.

Two things happened in the beta.166 release that make this more than routine
version churn:

1. The framework packages moved their own framework/peer dependencies out of
   `dependencies` (packaging hygiene), so **the consuming app is now
   responsible for supplying them**. `zod` is the one that matters here.
2. The workspace's shared dependency pins were refreshed (`next`,
   `react-hook-form`, `@tanstack/react-query`, `@types/react-dom`), and several
   of those had never been captured by any migration.

### Why `zod` is load-bearing

Before beta.166, `@igrp/framework-next` listed `zod` in its own `dependencies`,
so the app got a working copy transitively whether or not it declared one. As of
beta.166 it is a **peer** dependency. An app that upgrades the framework without
also bumping `zod` is relying on whatever version its own lockfile happens to
resolve — for apps scaffolded before this migration, `4.4.3`.

The template itself already declares `zod`, so this is a version alignment
rather than a new requirement. An app that has removed `zod` from its
`package.json` will see the CLI's
`⚠ package.json: not declared by this app, so NOT bumped` warning and must add
it manually — the framework will not supply it any more.

## What this migration deliberately does *not* change

- **`biome.json` / `@biomejs/biome`.** The workspace moved to Biome 2.5.11 and
  updated the template's `biome.json` `$schema` to match, but `biome.json` is
  not migration-managed (it is a consumer-owned formatter config — see the note
  in migration 28). Bumping the formatter binary without its config would ship
  half the change, and a formatter major/minor bump can rewrite a consumer's
  entire tree on their next `format` run. Both are left to the consumer.
- **`engines.node`.** The template changed `>=22.x.x` to `>=22`. These ranges
  are semantically identical and there is no step type for `engines`, so the
  cosmetic difference is not propagated.
- **Source files.** Nothing under `src/` changed in this release; the drift
  gate's payload axis was already clean.

## Notes for upgraders

- After applying, run your package manager's install so the new versions are
  actually resolved (`pnpm install`). `deps.bump` rewrites `package.json` only —
  it does not touch your lockfile or `node_modules`.
- `@igrp/*` versions must move as a set. The framework packages peer-depend on
  each other at these exact beta versions, so upgrading one in isolation
  produces unmet-peer warnings. Apply the whole migration rather than
  cherry-picking ranges.
- Rolling this migration back restores the previous ranges recorded in the lock,
  but — as with any `deps.bump` — it does not re-resolve your lockfile either.
